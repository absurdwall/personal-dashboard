Manual Dida writes use the existing discovered MCP schemas directly. Execute only the exact current user's authorized external effect: new tasks default to Dashboard unless Dida is specified, existing external objects retain their source and stable IDs, and clear reported completion can authorize that matching external object. Possibilities and discussion authorize no mutation. Resolve same-name or date ambiguity before writing. Putting a local Task into Dida needs explicit copy versus move intent; never delete the local original by default. Read the current object before changing it and preserve unrelated fields. Use actual Task status semantics exposed by the MCP (0 active, -1 abandoned, 2 completed), and check-in status semantics (0 unmarked, 1 not completed, 2 completed); do not guess Habit status/deletion meanings or pretend an unsupported real-time field exists. Keep historical check-in stamp distinct from opTime and supply the actual user timezone. Check-in range endpoints can exclude an exact-day query; read an adjacent-day envelope and select the requested stamp exactly before confirming saved state. The selected MCP generates creation IDs and ignores caller IDs. Record the returned stable source ID immediately. If a creation receipt is lost, reread search_task for its exact title or list_habits for its exact name and inspect current source candidates; matching names alone do not prove identity. Preserve that creation as unknown when identity cannot be confirmed, never repeat it automatically, and continue only the still-authorized remaining or unrelated current actions. Never claim saved because a mutation tool returned: read back the exact stable source object, verify requested fields, and separately report each saved/failed/unknown effect. Unknown effects must be read back before retries; sourceObserved means current source was read, not that the old requested effect succeeded. Preserve later edits and do not replay old effects to match stale fingerprints. do not recreate an object whose original outcome or identity remains unknown. Automatic and review-first rounds cannot mutate Dida. Prior external action metadata is history and recovery context, never permission to replay an old request. A request to review first gets a textual proposal only. Dida source changes do not change Dashboard data or refresh the Habit snapshot by themselves.
