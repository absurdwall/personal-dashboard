# Personal Dashboard — 已确认原型的日常体验改进

## 问题与目标

Today 的宽泛安排未进入时间轴，导致已有计划却看起来没有安排；用户也无法直接调整它的时间。Tasks 的列表操作与内容展示偏重，完成勾选不够清楚。Calendar 的有限空间需要容纳更多可读预览，并保留每天的记录与复盘状态。Collaboration 有重复标题和过多常驻说明，已有 `/retro` 能力难以发现；Evening 缺少清晰的复盘入口。

本轮落实用户确认的原型结构，使阅读、调整计划、完成任务和进入复盘更直接。继续复用真实 Daily Record、Task、Collaboration session 与既有 skills，不重新建立数据系统。

## 设计依据与优先级

- 视觉依据：[原型 R](prototype/README.md)，入口 `revised.html?page=today&variant=R`；Tasks 沿用用户确认的 B 列表结构。原型存于 `codex/dashboard-experience-prototype`，原型定稿记录提交 `e0e339b`；其后的问答细化写入规则。
- 语义依据：[Q1–Q3](design-review.md)、[CONTEXT](../../CONTEXT.md)、[ADR 0005](../../docs/adr/0005-let-codex-interpret-collaboration-write-intent.md) 与 [ADR 0006](../../docs/adr/0006-use-skill-led-conversation-for-collaboration.md)。
- **写入规则以 Q1–Q3 与本规格为准**。R 曾演示同时修改早间、当前安排两个段落；这不是最终规则。其内存 Task 时长也不是已有持久化能力。
- 历史 A/C/F 原型不再决定结构。不得把原型覆盖脚本直接当成生产实现合并。

## 功能与数据规则

### PDEX-01：早间文字与来源归属

Morning 保持文字安排和已有早间依据，不改成时间表。文字保留具体时间范围或原本的宽泛措辞；例如“午后”不能因为界面使用 13:00 定位而被自动改写成精确时间。

Morning baseline 与 Current arrangement 继续是不同的计划版本。早间规划或明确纠正早间安排时修改早间对应部分，保留初始证据与纠正痕迹。进入白天后的正常拖动不是早间纠正，即使当前条目最初来自早间，也只更新当前安排。

### PDEX-02：共享白天时间轴

Current arrangement、定时 Task 与 Confirmed facts 共享一条时间刻度及事件区域。保留来源标记；没有冲突时条目占整行，有冲突时临时并排，不按三类来源固定分三列，也不把卡片互相遮住。

保留 lived day 的 04:00 至次日 04:00 边界及真实日期标签。边缘无内容时可折叠；有内容时必须可发现和展开。时间轴自身滚动，不为了空白小时让整页异常拉长。长拖动支持边缘滚动，窄窗口下条目仍能选中、编辑和操作。

计划不会因时间过去而成为事实。Confirmed facts 不通过计划拖动操作改动；事实纠正继续使用明确的记录纠正流程，并写回事实来源。

### PDEX-03：模糊时间与精度编辑

具体时间点、具体起止时间与模糊计划可以共同显示。有稳定含义的宽泛措辞按确定性规则定位，初始参考为早晨约 09:00、中午约 12:00、午后约 13:00、傍晚/晚间约 18:00。规则不是用户实际活动时间，必须在卡片上明确显示“约”或原始宽泛措辞，视觉区分精确区间。

无法可靠定位的措辞仍保留在未定位部分，不通过 LLM 猜时间。“现在”等相对表达不能随着每次刷新而不断移动；只有记录本身包含足够时间上下文时才确定参考位置。

拖动模糊计划后保存新的近似时间，如“约 14:00”，保持模糊精度；卡片阅读高度不产生时长。用户可以明确切换为具体起止时间，也可把具体计划改为模糊时间。具体区间整体移动时保持时长，结束边界可以单独调整。精确时点保持时点，除非用户明确补充结束时间。

提供与拖动等效的时间编辑方式。实现默认以 15 分钟吸附方便拖动；已有非整刻时间读取时保留原值，不能在打开页面时被改写。

### PDEX-04：机械写回与保存结果

白天拖动或编辑 Current arrangement，机械修改 canonical Daily Record 的当前安排部分，并留下白天修订记录。它不自动修改早间部分、事实、习惯或 Task。Task 拖动只更新同一 Task，不顺手改写 Diary 计划。相似名称不建立联动关系。

使用可靠的条目身份与来源绑定；不能仅凭标题匹配、全文件替换相同时间字符串，或使用渲染位置作为持久身份。兼容旧文档，没有可靠身份或可安全修改的结构时，显示可理解的说明并提供重新读取/明确编辑，不能猜目标落盘。

写入前验证当前文件修订，保留无关 Markdown 和用户内容。修改时间、生成相应修订和读取验证构成一次一致保存；不会留下只有半份改动的结果。发生并发外部编辑时先报告冲突和刷新，不覆盖用户刚写的内容，也不自动重放旧拖动。

拖动时允许临时预览；保存成功必须经过真实落盘和重新读取确认，再更新相关页面。写入失败时恢复已保存状态，并保留用户可重试的编辑值。无法确定结果时明确标记未确认并重新读取核对，不能伪称成功。文档已保存但页面刷新失败时，两者结果分别表达。

这些修改由 App 的确定性持久化逻辑完成，无需 LLM、模型额度或额外语义授权关卡。保留既有来源、修订冲突和合法参数约束。

### PDEX-05：Task 执行时间段与列表

任务可以没有日期、只有日期、只有一个定时时点，或具有明确的计划执行时间段。时间段是准备执行的起止安排，不是截止时间或实际耗时；不推导完成状态。

空白时间轴选取一段区域可以创建一个 Task，保存其日期和执行时间段。整体拖动保持时长，编辑结束时间调整计划时长。重新打开 App 后仍显示同一时间段，Tasks、Today 和 Calendar 使用同一 Task 身份与保存值。已有单时间点任务不被赋予虚构结束时间；卡片最小显示高度仅供阅读。

兼容现有 Task date 语义及旧记录，不静默重标日期。跨午夜的执行区间需明确保存结束所属日期，并在界面显示次日标识；无效或超出支持边界的输入必须说明，不能丢失结束日期、截断时长或翻转起止时间。现有 Collaboration Task 操作与离线 daily-flow adapter 需兼容新字段：未传时保留原有时段，明确清除时才能移除，不因旧调用丢失结束时间。

Tasks 保留左侧清单侧栏；中心是清晰的任务名与完成勾选列表。点击名称/行选择任务并显示详情，勾选只改变完成状态。内容、日期、时间段和清单归属在详情区编辑；放弃、删除等次要操作集中在详情区。现有完成、放弃、重开、清单归属和历史能力仍可访问。

窄窗口可将详情放到列表下方或独立可返回面板；不以固定三栏挤压内容，不引入任务时间轴工作台。完成与未完成勾选有清楚的边界、状态和可点击区域。

### PDEX-06：紧凑 Calendar

每月实际需要的五行或六行日期网格均为等高格，不随某天任务数量变高。在 1280×720 和约 830×758 的参考窗口，月份标题、星期与整月网格可见；六行月也不能照搬五行月高度导致必须向下寻找最后一周。

默认每格最多四行单行任务预览，可省略尾部文本；更多数量提示放在日期行，点击日期后查看完整列表与记录。两行/四行展示可沿用原型控制，但不新增常驻解释区。预览不能覆盖状态标记或撑高格子。

日期右侧默认显示小型记录状态：已有记录未完成晚间复盘为“记”，已复盘为“复”，确实没有记录为空；加载错误不能表现为没有记录。复用现有真实状态，不以 Task 完成数判断是否复盘。右下角方案是原型比较选项，正式默认使用日期旁，不要求上线一个切换标记位置的设置。

### PDEX-07：Collaboration 减负与命令发现

保留 session 列表和主对话结构，去掉同一页面的重复标题。长背景/能力说明折叠或按需显示；会话草稿、听写、历史、停止、排队和可展开工作历史继续沿用既有能力。

输入 `/` 显示当前确实可用的命令，继续输入筛选；上下方向键选择，Tab/Enter 或点击补全文字，Escape 关闭。候选打开时 Enter 用于补全，不直接提交消息。与输入法组合输入兼容，普通含斜杠文本不误触发提交。

本轮至少展示已有 `/retro` Personal Retro 入口，附简短用途说明。候选从真实可用能力维护，不把 Workflow Retro 加入 Dashboard，不虚构尚未提供的命令。选择命令只插入可编辑草稿，用户另行发送；既有 usage skill 负责执行，不另建硬编码 Retro 流程。

### PDEX-08：晚间复盘入口

Evening 提供清晰的“开始今晚复盘”入口；查看过去日期时使用对应日期的措辞。打开明确目标日期的 Collaboration session，带入可编辑的复盘草稿和 Daily Record 上下文引用，不自动发送、不自动生成事实或把一天标记为已复盘。

已有适合继续的目标会话可复用，不因重复点击产生重复消息。目标会话已有草稿时保留并明确呈现如何继续，不静默覆盖；上下文进入会话不复制出另一份 Daily Record。真实复盘保存继续使用已有业务操作和技能。

## 验收标准

| ID | 必须验证的行为 |
| --- | --- |
| AC-01 | Morning 是文字视图；具体和模糊措辞与对应文档一致，没有第二条时间轴 |
| AC-02 | 白天具体计划 08–10 拖至 10–12，当前安排落盘并保留修订；Morning 与事实未变；重开仍正确 |
| AC-03 | 明确纠正早间安排只改其来源并保留纠正痕迹；不得误用白天拖动通道双写 |
| AC-04 | “午后”有明确近似标记；拖至约 14:00 后文件保留近似语义；精确/模糊转换落盘后可重新读取 |
| AC-05 | 无可靠时间的记录仍未定位；时间过去、拖计划、拖 Task 均不创建事实或 Habit completion |
| AC-06 | 冲突时条目临时并排且可选择；无冲突时整行；边缘拖动滚动可用，跨日标签明确 |
| AC-07 | 用区间创建 Task，移动、调整结束时间、重开后保存一致，三个页面展示同一身份；旧时间点无虚构时长 |
| AC-08 | 跨午夜区间保持起止日期；旧 adapter/Collaboration 更新不丢时段；无效起止清楚拒绝 |
| AC-09 | Tasks 的勾选和详情选择互不误触；清单侧栏保留，次要操作与历史可访问；窄窗口内容可读 |
| AC-10 | 五行及六行月份等高，参考窗口完整可见；四行预览不溢出，“记/复/空/读取失败”区分正确 |
| AC-11 | `/`、筛选、键盘/点击补全、Escape、中文输入法均可用；补全不发送，仅真实命令出现 |
| AC-12 | 晚间入口带入正确日期和草稿，保留既有草稿；重复点击不重复发送或误标复盘完成 |
| AC-13 | 文件写入失败、外部修订冲突和未确认结果都有真实状态，界面不会永久停在未保存的拖动结果 |
| AC-14 | 无模型额度时直接时间编辑仍可保存；原始 Markdown 无关内容、Daily Record 历史与既有 Task 兼容性保持 |

以合成 Vault/Profile 检查持久化、身份、修订冲突、跨日边界和适配器兼容，再在真实 Tauri 打包 App 验证页面、拖动、键盘、重新启动和保存后的文档读回。浏览器原型、单元测试或编译通过分别记录，不能替代打包 App 验收；不改用户真实数据做测试。
