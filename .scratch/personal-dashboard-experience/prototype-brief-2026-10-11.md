# 本轮体验原型任务说明

日期：2026-10-11。阶段：需求讨论和关键问答已完成，用户授权在新的 GPT-6.1 Sol / High session 中制作可丢弃原型。尚未授权正式产品实现、安装、发布或重新打开旧 tracker。

## 原型要回答什么

用可操作的比较把语言描述中尚不确定的布局、信息层级和编辑入口锚定下来。优先回答以下问题：

1. Today 怎样既能在较大窗口概览一天，又能点击、拖动和阅读短任务？详情浮窗与右栏哪种更顺？
2. Tasks 右栏怎样把空间还给 Content，同时让时间、清单、标签、优先级和父子任务容易操作？
3. Collaboration 怎样让消息、输入、context 和语音转写在不同窗口大小下自然共存？
4. Calendar 的日期回顾、任务浮窗、顶部新增入口及节日标注怎样共存？
5. Habits 的新增、编辑、打卡、详情统计及停用恢复怎样衔接？

不是重新设计整个产品。每个比较都应有明确问题；用户已确定的语义不能变成候选项重新投票。默认可提供三套在待定点上有结构差异的方案，沿用同一导航和合成样例，用 `?variant=` 与浮动切换条比较。对已定结构不强行制造三个不同方案，允许逐页择优组合。

## 复用基准

- 阅读 `.scratch/personal-dashboard-experience/prototype/README.md`。
- 最新旧原型是 `revised.html`、`revised.js`、`revised.css` 的 R 版。`index.html` A/B/C 和 `finalized.html` F 是历史候选，不是最新基准。
- 复用现有导航、外壳、样例、列表、时间轴、拖动及服务入口 `npm run prototype:experience`，不要从零搭工程或加入依赖。
- 保留旧 R 版可运行、可对照。在现有 prototype 目录内用明确的 refinement/prototype 文件名新增本轮变体，避免覆盖旧证据。不修改正式 `frontend` 或 Rust 产品代码。
- 旧 R 演示曾同时改早间和白天 Markdown；这是历史演示，不是这轮规则。新原型的白天调整仅更新 current arrangement，morning baseline 独立保留。
- 全部使用合成数据与内存状态，无真实 Vault、账户、外部写入、持久化、模型请求、麦克风采集或 App 安装。语音用模拟状态演示。

## 已确认需求

### Tasks

- 保留紧凑清单列表和右栏，任务行不要铺开全部属性。打开详情默认聚焦 Content。
- 顶部粗体标题可直接编辑，移除重复 Name 输入。Content 更大且靠上。
- 清单、日期和时间是紧凑属性入口，点开再设置；起止时间同一个编辑区，清除结束时间仅在有结束时间时出现并放在其中。
- Save / Cancel 同行、尺寸协调、主次清楚；未决定自动保存，不擅自换成自动保存。
- 子任务是普通 Task，拥有自己的内容、日期、清单和完成状态，可继续嵌套。父任务详情列直属子任务。父子完成状态互不级联。
- 文件夹归组清单，清单也可在文件夹外。箭头展开收起；点文件夹名看任务汇总，按原清单分组，不复制任务。All / Today / Inbox 保持独立。
- 快速添加可在创建前选择日期、目标清单，文件夹汇总中目标清单尤其要明确。现有日常快速添加默认日期沿用。
- 加入优先级高／中／低／无及标签，提供合理的选择与排序筛选演示；具体呈现交给原型。四象限明确暂缓。
- 右键菜单和详情 More 值得演示统一操作入口：日期、移动清单、状态、删除、与 Codex 讨论，以及添加子任务、关联／解除父任务。清单是候选设计，不意味着每一项已冻结；不额外扩大为复制、固定等新功能。

### Today

- 保持日视图，较大窗口能概览一天安排。紧凑时间尺度是比较起点，不只机械恢复旧数值；减少说明和留白，给时间轴更多高度。精细操作可放大。
- 当前产品每小时由旧 3.75rem 增到 5rem；用户只看到约五小时，感到明显退步。比较时展示相同窗口与样例。
- 点任务不跳到底部，不用午夜刻度下面的重复详情。就近浮窗或右栏查看和编辑，保留滚动位置；形式是本轮待比较项。
- Task、精确安排、宽泛或近似安排都可拖动。Task 区间移动保留时长。安排改 current arrangement，保留 morning baseline；事实不拖动，也不从时间经过推断完成。
- 宽泛的“下午”默认可摆在 13 点，但仍显示“下午”。主动拖到 16 点后才成为“约16:00”。
- 缩放和窄窗口可省略文字，但卡片边界、点击区域完整，不能奇怪地侧向截断；重叠卡片都能选到。
- 保留“取消时间安排”和“删除 Task”两个不同操作。取消时间只清时间及执行区间，保留日期，任务仍在 Today 列表及 Calendar；删除作用于同一共享 Task。Daily Record 的取消只更新当前安排，保留早间基准。

### Collaboration

- 常规聊天和输入体验参考 Codex。保留已认可的较大输入区和字体。
- 聊天区域适配窗口，输入和发送容易找到，消息独立滚动。
- 展开的 context 有自己的限高和滚动，不把整页撑长、不导致输入框下大片无效空白。变成底部区域时，自己标题旁有容易找到的收起入口；侧栏／底部／浮层可以比较。
- 语音是有意保留的差异：转写先显示在输入框下方，停止后进入可编辑草稿，再由用户发送。预览按需展开，空时不预留大片留白，出现时可完整看到。
- Slash 只补多候选的上下键选择，现有 Enter / Tab 补全及 Esc 退出保留，不加新的高亮样式。现有实现只有 `/retro` 候选且已有相关键盘处理，后续需要验证差距；原型可用明确标识的模拟多候选演示，不能暗示新增真实命令已获授权。
- 不改变模型／effort 的真实选择语义，不硬编码另一个执行模型，不引入另一层审批。

### Calendar

- 保留等高紧凑月历。点日期在右侧显示当天计划与复盘，那里可 Open full Today。
- 点任务在月历上方打开可编辑详情浮窗，背景位置不跳。
- 新增任务只用顶部加号：先选日期，再点加号，打开创建浮窗，日期带入所选日、明显可见且可修改。不需要日期格双击或右键新增。
- 同一 Task 在 Tasks / Today / Calendar 共用身份，不复制任务、不因添加 Task 而创建 Daily Record。
- 加入中国和美国节日轻量标注，可关闭，主要空间留给任务。原型节日是明确的样例，不添加外部服务；农历、节气、调休没有自动纳入。
- Calendar 周视图没有确认，不新增；Outlook 周视图仅是可读性参考。

### Habits

- 顶部加号新增本地 Habit，创建后可直接在 Dashboard 打卡，不要求先在 TickTick 建同一个 Habit。
- 新增与编辑共用设置：名称、频率／目标、开始日期默认今天，保留现有时间阈值类目标。Daily / weekly 清楚表达，不拆成令人困惑的重复字段。
- 左侧点 Habit 显示详情，详情有编辑入口，可演示右键编辑；编辑带入当前值并保留身份和历史。
- 每周目标按达标天数：每周三天／五天，同一天重复完成只算一天，不能当成多次运动场次。
- 详情显示本月打卡数、累计打卡数、当前和最高连续达标；每日按天、每周按连续达标周统计。累计和最高连续必须区分完整历史与有限覆盖，不能把近期数据冒充全历史。原型可演示有完整合成历史和覆盖不足两种状态。
- 目标修改从下个周期生效：每周从下周、每天从次日；本周期和历史按当时目标算。当前目标和待生效目标应能辨认。
- 停用后从日常打卡区收起，保留历史和统计，允许恢复。
- 可选简单 emoji 图标与分组已获认可，轻量演示即可。不加入永久删除历史、通知、计时器等额外功能。
