## 本轮问题与修订

1. **Today 同一条时间轴**：计划、事实、Task 共享刻度与事件区域，没有按来源固定拆成左右两条轴。仅在相互重叠时并排排布。早间与白天页均使用该结构，lived day 的 04:00–06:00 和次日 00:00–04:00 保留边界说明。
2. **模糊时间也定位**：示例将早晨／中午／午后／晚间分别放在约 09:00／12:00／13:00／18:00。条纹与“模糊计划”明确标识近似位置；卡片高度只是阅读空间，不代表精确时长。拖动到其他位置后仍为“约 HH:MM”，不会自动变成精确范围。点击计划可在模糊与具体起止时间间切换。
3. **机械文档同步**：拖动、修改精度、调整结束时间，通过同一条计划 id 直接改变时间字段，同时更新“早间计划”和“当前安排”的 Markdown 预览。点击“查看对应文档”可检验文本，改动前初始快照与每次修改保留。没有调用 LLM，也没有新增审批步骤。示例 Markdown 仅用于展示对应关系，不是生产 Daily Record 格式契约或持久写入实现。
4. **Tasks 以原版 B 为基础**：保留清单侧栏，中心简洁勾选列表，点击任务在详情区查看内容／日期／时间／列表，不把长说明和多个操作铺在每行，也不做任务时间轴工作台。增强勾选框保留。
5. **Calendar 每个日期格等高**：本月 35 个格子使用相同高度，空日期与四行任务日期都相同。保留“记／复”右下角标记，默认四行预览，更多任务显示剩余项数。

## 文档规则差异待确认

用户本轮明确提出拖动后早间计划和白天规划对应内容自动变化。因此 R 演示“用户显式修改同时更新两个计划段落，保留改动前版本”。这与 [CONTEXT](../../../CONTEXT.md) 中当前 arrangement 改动保留 morning baseline 的规则不同；此次**没有更改 CONTEXT、ADR 或正式产品**。整体原型接受后，需要在规格中明确可编辑计划、原始基准和修订历史的身份与写入归属，再做有边界的实现。

现有 Task 尚无持久时长字段；原型选区长度用于体验演示，不是正式时长契约。`/retro` 补全仍只是已有 skill 对话的可发现入口，不发送消息、不硬编码另一个执行模型。
