# Personal Dashboard 协作与 Today 界面验收修复

Status: ready-for-agent
Document kind: spec
Scope: 规格发布；拆票和代码实现由后续流程启动。

## Problem Statement

PR #35 合并并更新日常安装后，用户实际使用发现三项界面验收不通过：协作窗口稍窄就从三栏直接退到一栏；Today 的长时段标签会把右侧正文挤成细长条；时间轴的早间／深夜展开按钮位置和交互不符合预期，Locate Now 也过于显眼。

用户已明确这些期望，无需重新进行完整设计访谈。本轮补足原规格在具体布局和交互上的约束，并把真实候选版本的用户验收放在 merge 之前。既有自动测试与代码审查记录是技术证据，不能替代用户确认界面符合预期。

## Solution

**协作布局**：宽窗口保留 Sessions、conversation、Current context 三栏；稍窄时先收起 Current context，保留 Sessions 与 conversation 两栏。Sessions 占较少宽度，将主要空间留给 conversation，包括当前选中的 automatic morning plan 会话。Automatic morning plan 沿用现有会话／工作流程，不新增第四个区域。用户仍可主动收起、恢复辅助栏并调整宽度。

**Today 长内容**：时段标签与正文都应可读。长标签可换行，并限制其占用的横向空间；横向空间不足时将标签和正文上下排列。正文使用合理可读的宽度，避免逐字形成极高细条，也不以隐藏正文或裁掉关键信息作为解决办法。

**时间轴控件**：04:00–06:00 的展开入口位于时间轴顶部，次日 00:00–04:00 的展开入口位于底部，分别在原位置展开／收起对应时段。它们不再作为顶部的一组导航按钮。Locate Now 保留独立功能，作为时间轴标题附近靠右的小图标按钮；主动定位时使当前时段可见。

**合并条件**：修复后先交付隔离的可运行 Mac 候选版本，用户实际查看并确认本轮界面修复通过后，再取得明确 merge 同意。自动化通过、代码审查通过、可合并状态均不得被写成用户验收通过。

## User Stories

1. 作为用户，我希望宽窗口保留三栏，以便同时查看会话历史、对话和当前上下文。
2. 作为用户，我希望稍微缩窄窗口后仍保留 Sessions 与 conversation 两栏，以便继续切换和阅读会话。
3. 作为用户，我希望两栏时 Sessions 更紧凑、conversation 更宽，以便把空间用于当前工作。
4. 作为用户，我希望 automatic morning plan 会话沿用普通对话的可读布局，以便继续在 Dashboard 中处理早间计划。
5. 作为用户，我希望两栏时仍能按需查看 Current context，以便不会丢失辅助信息入口。
6. 作为用户，我希望自己主动收起或展开栏位的选择得到尊重，以便按自己的方式工作。
7. 作为用户，我希望拖动分隔线和恢复保存宽度时内容仍放得下，以便旧偏好不会挤坏新布局。
8. 作为用户，我希望缩窄、放宽或重新打开窗口不丢草稿和会话选择，以便连续工作。
9. 作为用户，我希望“白天（具体时段未定）”等长标签合理换行，以便读懂它又不牺牲正文空间。
10. 作为用户，我希望窄窗口中标签和正文可上下排列，以便正文保留可读行宽。
11. 作为用户，我希望长中文、英文和中英混合正文都正常折行，以便不会形成逐字细条或横向溢出。
12. 作为用户，我希望完整正文、来源和已有详情操作仍可访问，以便修复排版不会减少信息。
13. 作为用户，我希望短内容仍保持紧凑，以便修复长文本不让所有条目无谓膨胀。
14. 作为用户，我希望在时间轴顶部展开 04:00–06:00，以便理解这段内容在一天中的位置。
15. 作为用户，我希望在时间轴底部展开次日 00:00–04:00，以便自然继续查看深夜安排。
16. 作为用户，我希望两端可独立展开和收起，以便只查看所需时段。
17. 作为用户，我希望展开时保持当前位置和阅读连续性，以便不会被跳转打断。
18. 作为用户，我希望 Locate Now 是容易找到但不抢眼的小图标，以便标题区保持简洁。
19. 作为用户，我希望定位现在能自动显示折叠时段中的当前时间，以便凌晨使用仍然方便。
20. 作为键盘用户，我希望展开入口、栏位控件和定位图标有可访问名称、状态和可见焦点，以便不依赖鼠标完成操作。
21. 作为用户，我希望时间轴日期、卡片、重叠展开和源记录都保持正确，以便交互修复不破坏生活日语义。
22. 作为验收者，我希望看到可运行候选版本及对应测试结果，以便基于实际界面决定是否接受。
23. 作为验收者，我希望我反馈的不通过项被修复并重新展示，以便未达到预期的版本不会先被合并。
24. 作为验收者，我希望清楚区分本轮界面修复与旧票未完成的其他验收，以便不会误以为语音或协作写入也已经通过。

## Implementation Decisions

- **基线与范围**：以 PR #35 已合并成果为修复基线，保留已确定的 04:00 生活日、目标日期、任务身份、历史记录和写入权限规则。修复现有界面，不引入新页面架构或业务存储。
- **三栏到两栏的过渡**：在仍可容纳紧凑 Sessions 与可用 conversation 的宽度下，自动布局须优先保持两栏。只有确实不能容纳两栏的极窄情况或用户主动收起 Sessions，才使用单栏。具体阈值按实际内容区域验证；不把旧实现的单个窄屏阈值照搬为新的验收标准。
- **两栏内容与比例**：默认收起右侧 Current context，左侧 Sessions 更紧凑，对话占主要可用空间。原有 Current context 入口仍可访问；空间不足时按需显示不得重新迫使整页横向滚动。
- **偏好与布局恢复**：区分用户主动收起与系统因宽度自动调整。新布局应兼容已保存的栏宽和显示偏好，宽度变化后重新约束到有效范围，不因已有默认窄屏状态而永久跳过两栏，也不静默清空全部偏好。保留会话、草稿、焦点及键盘调宽能力。
- **长文本排版**：调整已有时段标签／正文的宽度分配和响应式排列。长标签不能无限占用横向空间；必要时上下排列。正常中文和英文句子以可读行宽折行，长无空格片段可安全换行。保留完整内容、来源标记和展开详情，不改变原始 Daily Record。
- **时间轴边界入口**：早间入口与时间轴开始边界相邻，深夜入口与结束边界相邻；展开后分别在该端增加原本折叠的时间范围。两端状态独立、可逆，显示对应时段和展开状态。
- **原地展开**：展开／收起保持当前可见内容的阅读锚点，不自动执行 Locate Now，也不把用户滚动到远端。用户明确点击 Locate Now 时才定位当前附近；若当前时刻处于折叠端，先使对应范围可见。保留原有凌晨初次打开时当前时间可见的行为。
- **定位图标**：放在时间轴标题区域靠右的次要位置，视觉上简洁，同时保持足够操作面积、工具提示、可访问名称和键盘焦点。删除原来的三个显眼并列按钮呈现；早晚展开功能迁移到对应边界入口。
- **保留时间轴行为**：完整生活日仍为当日 04:00 至次日 04:00，默认主体仍为 06:00–24:00。次日标签、卡片原时间锚点、重叠 reveal、卡片详情、无精确时刻条目和手动浏览保护均继续成立。
- **沿用现有模块与边界**：修改现有协作栏位布局、Today 条目呈现、时间轴交互及必要的界面文案；Rust 产品行为、真实时间戳和持久化契约保持现有语义。无新增依赖、服务或 schema 的已定需求。
- **交付门槛**：后续 PR 在用户看过候选版并确认前保留 draft，验收反馈修复后再次提供候选版。验收通过与 merge 授权分别记录；没有明确 merge 同意就不合并。日常安装更新也需明确授权，候选版优先使用隔离安装与临时数据。

## Testing Decisions

用户已确认验收入口：真实 packaged Mac App 的宽／稍窄窗口、长标签与正文、时间轴原地展开，配合同场景自动化，最终由用户看过候选版并确认后再 merge。以下方案尚未执行。

- **主验收入口**：复用现有 packaged Mac App 与隔离 Vault 的界面操作流程。用同一组合成数据检查宽窗口、常用稍窄窗口、极窄窗口及重新放宽，保存候选构建身份、实际窗口尺寸和截图，交给用户查看。截图是补充证据，可运行候选版仍须可供用户操作。
- **回归先行**：修复前在合并基线上复现对应失败，建立能检测用户具体症状的回归；修复后以相同输入及窗口条件复跑。既有静态源码断言或测试总数不足以证明排版正确。
- **已有入口优先**：扩展现有 collaboration panels 行为测试、编译后 lived-day renderer 回归、时间轴测试和 packaged 窗口操作场景。几何计算和状态边界可有少量模块测试；真实排版必须通过实际渲染结果与可见操作验证，不新增平行验收框架。
- **协作验收矩阵**：验证三栏→两栏→必要时单栏→恢复；稍窄窗口下 Sessions 和 conversation 同时可见，对话占主要空间，Current context 可访问。覆盖默认偏好、旧保存偏好、主动收起、调宽、重启恢复、中英文界面及草稿保留。断言内容可见和空间分配，不只断言页面无横向滚动。
- **Today 文本矩阵**：复现“白天（具体时段未定）”搭配较长正文的场景；组合短／长标签、短／长中文正文、英文和中英混合、长无空格字符串。验证合理折行、必要时上下布局、正文可读宽度、完整内容可访问，以及没有逐字极高细条、重叠或横向溢出。测试实际渲染区域，不只检查是否存在换行 CSS。
- **时间轴验收矩阵**：验证早间入口在上、深夜入口在下；分别展开、同时展开、独立收起；展开前后当前阅读锚点稳定。Locate Now 小图标可用，凌晨定位会显示对应折叠时段；继续验证次日标记、跨午夜卡片、重叠 reveal、详情操作和手动浏览不被抢回。
- **用户确认**：验收记录分别列自动化结果、代理实际界面检查、用户意见及用户确认的候选构建。用户指出任一目标场景不通过时，保持未验收状态，修复后再展示。影响界面的后续变更需要对应场景重新验收。
- **数据与范围回归**：使用隔离合成数据，确认显示和展开操作不会改变原始记录、Task 日期、习惯完成或协作写入目标。自动化验证及用户验收均不以修改真实个人记录为前提。
- **旧验收债务分开列示**：本轮三项界面验收与 #28–#34、#19 的剩余验收逐项区分。本轮通过不能自动关闭真实语音、原生协作 proposal／approval／write、物理 sleep／wake 等尚未核实的条件。核对其最新状态后按各自原票跟进。

## Out of Scope

- 本轮 spec 发布之外的实施拆票、代码修改、PR merge 和日常安装替换。
- 重新定义 04:00 生活日、修改日期语义、迁移既有个人记录或自动更正历史数据。
- 新语音识别方案、中英混合识别、模型安装，以及与本轮三项界面问题无关的旧验收修复。
- 全页面视觉重设计、新增 automatic morning plan 区域、替换协作工作流程或增加云服务。
- 将所有旧票一并标记完成，或以本轮界面修复替代其原始验收。
