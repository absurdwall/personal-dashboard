# Personal Dashboard — App 内 Codex 协作

Status: superseded
Stage: 历史版本；2026-09-27 已由 GitHub Issue #11 取代。
Date: 2026-09-26
Product version: 用户暂称新 4.0；独立于既有 Tasks 阶段的 personal-dashboard-4。
Execution boundary: 本轮只形成规格。下一阶段是用户单独启动 prototype，再据原型修订规格；此规格不授权跳过原型直接实现、拆票、安装或迁移真实数据。

## Problem Statement

用户已经在 Personal Dashboard 查看和维护任务、日历、习惯与 Daily Record，但早间计划、白天调整和晚间复盘仍需要到外部 Codex 交流，再回 App 查看结果。上下文、执行过程与实际结果分散在不同工具中。

需要搬入 App 的是一段持续的 Agent 工作：交流、读取数据、调用工具、修改多个对象、处理补充或中断，再继续工作。单次生成文字或只在 Today 增加聊天框不足以承载这些交互。现有页面已经密集，需要独立空间。

用户已有长期个人背景和每日流程规则，但缺少持续维护近期衔接信息、可靠更新长期背景的机制。新会话应能延续相关背景，同时以最新任务与记录为事实来源。

## Solution

在 Today、Tasks、Calendar、Habits 之外增加独立 Collaboration workspace，名称待原型探索。左侧默认展示当天的 Collaboration sessions，提供日期导航找回历史；一天可以有多个会话，会话可跨天继续并处理历史或未来安排。

用户在空间内以文字或语音输入，与 Codex 讨论早间计划、白天变化、晚间复盘及其他日常管理事项。Agent 可以执行现有 App 的日常数据操作，覆盖任务增删改、清单与状态管理、习惯补记和历史记录修正，不限定今天。明确指令可直接执行；模糊状态或探索性讨论先形成建议。

对话、执行状态和正在处理的计划／任务／记录共同呈现。变更写入既有正本，并同步反映在现有页面；会话历史不成为另一套任务或日记。设置内管理 Codex 连接。运行基础采用本地 Codex App Server，不额外引入 Agents API。

一个主 Skill 规定工作方法；复用现有业务操作提供工具能力；现有长期个人背景、近期衔接记忆和原始记录共同支持连续使用。自动早间计划可启用并设置时间：App 运行时到点生成，错过时间后当天打开 App 时补生成；已有计划不覆盖。完全退出 App 后不进行无人值守工作。

## User Stories

1. As an App 用户, I want 在设置中连接 Codex, so that 我可以直接在 App 内获得 Agent 协助。
2. As an App 用户, I want 看清连接、登录和不可用状态, so that 我知道是否能够开始工作以及如何恢复。
3. As an App 用户, I want 选择运行环境提供的模型设置, so that 我能使用适合当前工作的能力。
4. As an App 用户, I want 一个独立协作入口, so that 现有 Today 等页面不继续拥挤。
5. As an App 用户, I want 默认看到当天会话列表, so that 我能迅速继续当天的工作。
6. As an App 用户, I want 按日期找回历史会话, so that 我能查看过去怎样讨论和处理事情。
7. As an App 用户, I want 同一天创建多个会话, so that 不同事情不必挤在同一段交流里。
8. As an App 用户, I want 继续跨天会话, so that 尚未结束的讨论可以自然延续。
9. As an App 用户, I want 清楚知道当前正在处理的记录日期, so that 历史修正不会误写到今天。
10. As an App 用户, I want 从 Today 或具体任务进入协作并携带对象上下文, so that 我不必重复说明自己指的是哪件事。
11. As an App 用户, I want 使用文字交流, so that 我能精确说明需求。
12. As an App 用户, I want 在 App 内语音输入并看到可核对的文字, so that 我能自然讲述状态并纠正识别错误。
13. As an App 用户, I want 看到 Agent 正在读取、处理或等待什么, so that 长时间工作不是一个无反馈的等待。
14. As an App 用户, I want 工作中补充或纠正要求, so that Agent 能跟上我的最新意图。
15. As an App 用户, I want 停止正在进行的工作, so that 我能改变方向。
16. As an App 用户, I want 明确区分建议、待执行动作和已完成修改, so that 我不会误以为一句回复等于保存成功。
17. As an App 用户, I want 查看部分完成和失败结果, so that 我知道还有什么没有做完。
18. As an App 用户, I want 重开 App 后查看会话并继续工作, so that 我的交流和已完成结果不会丢失。
19. As an App 用户, I want 多会话的 Agent 工作依次执行, so that 它们不会同时覆盖同一 Vault 的安排。
20. As an App 用户, I want 等待期间仍能浏览和准备其他会话输入, so that 工作队列不阻塞整个 App。
21. As an App 用户, I want Agent 读取最新任务、习惯和相关日记录, so that 它不会只根据旧聊天决定怎么做。
22. As an App 用户, I want 与 Agent 制定早间计划, so that 计划能结合我的真实精力和安排。
23. As an App 用户, I want 白天报告事件或要求重排, so that 当前安排与实际情况一致。
24. As an App 用户, I want 晚上结合真实记录复盘, so that 未观察到的活动不会被当作失败或完成。
25. As an App 用户, I want 新增、编辑、改期和删除任务, so that 对话能完成实际任务管理。
26. As an App 用户, I want 完成、放弃、重新打开或恢复任务并修正完成日期, so that 状态错误可以纠正。
27. As an App 用户, I want 管理任务清单和任务归属, so that 协作中的组织能力与现有 App 一致。
28. As an App 用户, I want 补记或撤回本地习惯完成, so that 今天和历史习惯记录都能维护。
29. As an App 用户, I want 修改有误的历史笔记、计划或复盘, so that 历史事实可以纠正并保留必要痕迹。
30. As an App 用户, I want 在 Tasks、Today、Calendar 和 Habits 看到同一份修改结果, so that 不出现会话专属副本。
31. As an App 用户, I want 明确指令直接执行、含糊意图先讨论, so that 使用顺畅且不发生无依据的修改。
32. As an App 用户, I want 查看改动并进行适用的撤回或纠正, so that 我能恢复被误解的操作。
33. As an App 用户, I want 明确区分本地与外部来源, so that 同名事项不会被错误合并或双向修改。
34. As an App 用户, I want 必要时明确要求操作已连接的外部来源, so that 偶发外部需求不被产品人为禁止。
35. As an App 用户, I want 外部服务不可用时仍能完成本地流程, so that Dashboard 日常使用不依赖 Dida365。
36. As an App 用户, I want 延用现有个人背景和作息参考, so that 新 App 协作不从零认识我。
37. As an App 用户, I want 自动整理近期情况和未结束的讨论, so that 更换会话仍能衔接。
38. As an App 用户, I want 明确表达的长期变化被记录, so that 不必每次重复自己的偏好。
39. As an App 用户, I want Agent 推断的长期结论先向我核实, so that 临时状态不会被固化为个人特征。
40. As an App 用户, I want 查看和纠正记忆并获知实质更新, so that 我能理解未来建议依据什么。
41. As an App 用户, I want 保留原始会话和日记录, so that 摘要有遗漏时仍可回查。
42. As an App 用户, I want 启用并设定自动早间计划时间, so that 无需每天重新发起同一个请求。
43. As an App 用户, I want App 运行时到点自动保存计划初稿, so that 早晨可以直接查看和调整。
44. As an App 用户, I want 错过触发时间后打开 App 自动补生成, so that 不必保持 App 整夜运行。
45. As an App 用户, I want 已有计划被保留, so that 再次打开或重复触发不会覆盖我的安排。
46. As an App 用户, I want 较晚生成的计划尊重已过去的时间, so that 不会虚构早上发生过的活动。
47. As an App 用户, I want 自动规划不擅自修改实际任务, so that 计划建议和正式行动仍然清楚区分。
48. As an App 用户, I want App 运行时切页面仍能继续工作, so that 我可以同时查看其他内容。
49. As an App 用户, I want 退出后已完成结果保留且未完成工作可检查, so that 下次继续不会重复操作。
50. As an App 用户, I want 新旧自动规划在启用时明确交接, so that 两套定时任务不会重复生成。

## Implementation Decisions

### 已确认的产品与运行边界

- 增加独立 Collaboration workspace，与既有页面联动。现有页面仍负责各自日常查看和手动操作。
- 会话与 Daily Record 的日期身份分离。默认日期筛选为今天，一天允许多个会话；允许跨天继续及处理其他日期。跨天会话的列表归属是待原型确认的呈现细节，不能通过强制截断会话解决。
- 当前交付设计面向本地 Mac Tauri 应用，沿用 Rust 业务核心和现有前端基础，不因集成 AI 更换框架。登录和执行以 Codex App Server 为基础；不是将 Codex 桌面窗口嵌入 Dashboard。
- 沿用 Codex 管理的 ChatGPT 登录路径；展示真实连接能力和失败。运行版本、发现与分发方式需实现前核实，不把同一账号等同于所有客户端聊天或插件自动共享。
- 不引入 Agents API、Agents SDK 或新的云端 Agent 运行服务。新依赖或外部服务仍遵循项目明确批准要求。
- 一个主 Skill 负责每日协作和本地操作语义，沿用现有每日流程经验。工具负责实际执行，Skill 不是存储或权限校验的替代品。
- Agent 能力覆盖现有日常数据操作及既有 Codex 日常管理流程，不限今日，不以“只做早间规划”缩减最终范围。系统设置、Vault 管理等非日常数据操作不自动获得任意执行权限。
- 明确、唯一的修改指令直接执行；歧义、模糊状态和探讨性表达先讨论。保持必要的运行时审批，不额外逐条重复确认已授权操作。
- 同一 Vault 同时最多一项 Agent 工作，包括手动和自动工作。其他请求排队或由用户停止当前工作后切换；浏览和输入草稿不被阻塞。
- App 运行期间工作持续，切换页面不打断；完全退出后不运行无人值守 Agent。恢复会话与恢复未完成动作是不同操作，恢复前核对已完成结果。

### 操作与数据

- 复用现有 Task、Today、Habit 与 Daily Record 应用服务及其验证、条件保存和操作身份。完整工具集扩展到任务清单、编辑、删除、恢复、历史修正等现有能力，不能停留在旧外部任务适配器的子集。
- 当前任务、习惯本地完成和 Daily Record 保持各自正本；协作历史和记忆不创建第二份业务状态。App 各页面从同一业务结果刷新。
- Skill 当前内容与旧集成文档存在本地任务接线不一致，实施前必须按实际能力统一；不得把文档声称的接线当作现有实现。
- 初始计划、早间校准、白天重排、事件记录与历史纠正遵循既有 Morning baseline／Current arrangement 区别。纠正历史不被禁止，但应针对明确错误并保留适当修正痕迹。
- 计划生成和重排需要完整的应用级写入能力，不能只复用已有追加白天条目或复盘文本的窄操作便宣称完成。
- 操作开始及关键写入前读取所需最新数据；保留目标 Vault 绑定、版本冲突和重试去重。即使 Agent 串行执行，也要处理用户手动编辑或文件同步造成的并发变化。
- 工作可跨多个对象；不得暗示已经具备跨全部数据源的原子事务。逐项呈现成功与失败，重试不重复创建或覆盖新修改。撤回优先复用已有恢复和修正能力，不承诺任意外部动作都可一键回滚。
- Dida365 等外部来源不是核心默认依赖，不编写专门的 Dida365 操作 Skill 或将其设为本地每日流程前置条件。用户明确要求且连接可用时允许按需操作，保留来源、不模糊合并、不自动双向同步；不可用时明确说明。
- 现有习惯目录及外部快照仍需尊重其数据语义；本规格不等同于已经完成外部来源迁移或构建新的通用习惯引擎。缺失外部事实保持未知，不能阻塞独立的本地工作。

### 记忆

- 沿用现有长期个人背景、作息和习惯参考，不另建重复个人档案。
- 近期衔接记忆自动整理并淘汰过期内容，记录近期情况和未结束事项；它不替代正式任务和最新完成状态。
- 用户明确表达的长期变化可直接更新；Agent 自行归纳的长期判断先核实。单日状态默认留在当天记录或近期记忆。
- 原始会话和 Daily Record 保留，不采用每日只留下滚动摘要、删除原始材料的策略。
- 记忆可查看、纠正，实质修改给出简短提示。维护不强制依赖晚间复盘完成；具体整理触发与大小控制由实现设计决定并经原型反馈调整。

### 自动工作

- 自动早间计划由用户启用并设置触发时间，六点只是示例，不是固定时间。
- App 运行时到点入队；当天在设定时间后打开 App 且仍无计划时补生成。执行前重新检查计划存在性，避免排队期间用户已创建计划后又覆盖。
- 已有计划不被重复触发或再次打开覆盖。空壳 Daily Record 不等于已有有效计划；损坏或读取失败也不等于不存在。
- 允许无需当天再次口头授权便生成并保存初稿；自动初稿不擅自新增、删除或修改实际 Tasks。较晚生成仅据事实安排，不虚构已过去时间的实际活动。
- 主动提醒和记忆整理仅在 App 运行期间考虑；提醒具体触发和表现留给原型，不据此扩展成新的通用自动化平台。
- 不在本规格编写阶段修改已有 scheduled task。将来激活 App 自动规划时，明确原有外部定时流程的交接，避免两个写入者重复生成。

### 原型假设与待验证细节

- 原型起点为左侧日期筛选和会话列表、中间对话与简短工作状态、可展开的当前工作内容区域；右侧按计划、任务、复盘或历史对象变化。布局是候选，不是已验收视觉方案。
- 默认展示可理解的进度和改动摘要，技术调用细节按需展开。等待用户、执行、完成、部分失败、中断与排队应明确区分。
- 语音输入和可核对文字属于范围；具体识别方案待技术确认。连续实时语音通话及语音回复没有在本轮确定为必需能力。
- 正式名称、跨天会话排序、提醒外观、记忆入口位置、窗口收缩行为由原型探索，不再次发动广泛需求访谈。

## Testing Decisions

以下测试边界已获用户确认，作为本规格的验证方案。

- 以一个主要的协作应用服务入口作为新增测试边界：输入用户请求、时钟或生命周期事件，经实际业务服务执行，断言对外工作状态、持久结果及各视图读到的内容。此入口是设计建议，当前还未实现。
- 优先复用既有任务、Today、习惯与 Daily Record workflow 测试的临时 Vault、固定时钟和真实持久层。Codex 连接采用可控模拟传输驱动工具请求、等待、错误和中断，不把模型措辞或思考顺序作为测试断言。
- 沿用 daily-flow integration 的真实进程入口测试经验，但明确既有模拟外部来源和预置动作演练不证明真实模型选对工具或正确理解中文意图。
- 自动化重点覆盖：任务完整生命周期和页面共享身份；历史修正；基准保留；显式修改与建议区分；外部来源不可用；过期版本拒绝；重试去重；部分成功与恢复；多会话串行与最新上下文；长期推断需确认；近期摘要不覆盖事实。
- 自动规划覆盖到点、关闭后晚开、设定时间前打开、已有计划、只有空记录、损坏记录、重复触发、排队期间计划已产生，以及晚生成不虚构过去事实。退出后无 Agent 工作。
- 会话测试覆盖当天多会话、按日期找回、跨天继续、重启恢复、选中对象和目标日期传递，以及不同 Vault 隔离。日期归属展示断言在原型确定规则后补齐。
- 前端测试覆盖用户可见状态和交互；不为可逆排版变化编写镜像实现的测试。原型浏览器检查只证明交互和视觉，不证明真实 Agent 集成。
- 独立进行真实 Mac 安装包验收：使用真实 Codex 登录和执行、语音输入、完整早间—白天—晚间交流、工具修改与页面联动、重启与中断，以及自动触发。优先用明确隔离的验收数据，自动测试不碰个人数据。
- 好的测试证明用户实际结果与持久一致性，不检查私有函数拆分、固定工具调用数量或生成文字逐字相同。自动化、真实模型行为和安装包验收分别报告证据，不互相替代。

## Out of Scope

- 本轮产品实现、拆分实施票、运行原型、安装 App、实际登录、执行真实日常规划或修改个人记录。
- 正在进行的 3.0.2 刷新可靠性、时间轴联动、任务卡布局及四页一致性修复；本规格依赖其最终稳定接口，不接管该工作。
- 覆盖、重命名或混用此前 Tasks 阶段的既有 4.0 规格与 tickets。
- 完全退出后的后台 Agent、云端无人值守运行、独立守护进程或通用自动化平台。
- 多 Agent 同时修改同一 Vault；新增 Agents API／SDK 架构。
- 将 Dida365 作为默认必需后端、专门建设其写回流程、自动双向同步或未经请求迁移外部数据。
- 改变现有 Vault 云同步责任；本地保存成功不宣称云同步完成。
- 以聊天、记忆或新日记副本替代现有正式数据。
- 自动推断并写入长期人格判断、以未记录等同未完成、自动将建议升级为任务。
