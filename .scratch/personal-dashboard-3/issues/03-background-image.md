## Answer

在“外观”设置中新增了本地背景图片选择、预览、移除与恢复默认。原生 Mac 选择器仅接受 PNG、JPEG、GIF、WebP；选中后先验证格式及系统可解码性，再以内容寻址文件名原子写入应用数据目录，偏好只保存应用自有引用。取消、空文件、超过 20 MB、伪造图片或解码失败均保留当前选择；原始文件移动后仍可使用自有副本。自有副本缺失或损坏时显示可恢复状态，仍可移除或替换。

删除和替换只解析受控文件名并只触及应用的 `background-images` 目录，不删除用户原图或 Vault 文件。若自有副本清理失败，待清理文件名会继续持久化、错误会在设置中可见，并在下次加载外观时重试，避免把未完成清理误报为成功。恢复默认会同时恢复森林绿和无图片，但保留界面语言、Vault 选择与内容；图片偏好继续独立于 Vault，也没有上传或 Vault 写入路径。

页面层面由共享背景变量驱动 Today、Calendar、Habits，并使用轻薄白色内容层和边界；Calendar 内层改为透明以避免叠白，Habits 保持紧凑结构。验证通过：`npm run test:frontend`（37 项）、完整 `cargo test --manifest-path src-tauri/Cargo.toml`（169 项）、`npm run check`、Rust format、shell／Swift driver syntax check、release `.app` 构建，以及隔离 app data／合成 Vault 的 `background-image` packaged Mac 场景。打包场景通过真实文件选择器覆盖浅图、复杂图、无图，森林绿／雾蓝／赤陶，以及 1120×760 和 800×640；它比较三个页面主内容区的实际背景像素签名，并直接对照 Calendar 单元格内部与相邻页面层，验证取消、损坏拒绝、源文件移动、重启、损坏副本恢复、移除和恢复默认，同时确认合成 Daily Record、语言与 Vault 偏好不变。

提交：`feat(dashboard): add local background images`。限制：背景图片是这台 Mac 的本地应用数据，不跨设备同步；完整界面逐像素原型对照仍属于 09 票。
