## 01：Today 与习惯按凌晨 4 点切换生活日

Blocked by: None (can start immediately).

交付：凌晨在 Today 记录 Daily Record 或本地习惯时，默认仍归前一个生活日；04:00 后新操作默认进入新生活日。用户可看到并显式选择归属日期，跨边界的已有编辑保留原目标。

- [ ] 复用并扩展现有时钟边界，将生活日判定与真实时间戳分离；Today 与本地习惯展示、写入校验采用同一规则。
- [ ] 03:59:59 归前一生活日，04:00:00 归新生活日；重新打开及休眠恢复重新判定默认日期。
- [ ] 手动选定日期、已开始的编辑和待确认写入保留目标，显示日期与最终持久化一致。
- [ ] 自然日期、真实时间戳、显式 Task 日期／时间和已存历史归属不被批量更改；外部习惯证据保持来源与原日期。
- [ ] 在已有服务测试覆盖月末、年末、夏令时边界；以隔离 Vault 的 packaged App 路径证明记录、刷新和重启后的归属。
- [ ] 此票只交付默认日期及记录闭环；跨午夜时间轴展示由 02 交付，协作接入及语义由 03 交付，不能提前宣称整份 spec 已完成。

必要的局部整理首先在本票中完成：让生活日成为独立判定，不将原有所有自然日期调用机械替换。保留当前调用的语义和兼容行为，不单列广泛重构票。

## 02：完整生活日时间轴与活跃时段聚焦

Blocked by: 01（复用统一生活日与目标日期语义）。

交付：所选生活日展示当天 04:00 至次日 04:00，默认突出 06:00–24:00，两端可展开；次日凌晨安排、真实时间和“现在”均可直接理解与访问。

- [ ] 查询与界面共同覆盖完整生活日，04:00 边界不遗漏或重复；次日凌晨显示日期标记。
- [ ] 有时刻 Task 按实际日历时间投影，Calendar 中的明确日期不变；无时刻事项仍可见但不虚构时刻，跨午夜展示不复制 Task 或完成事实。
- [ ] 已存 Daily Record 与习惯事实保留原来源及归属，时间轴展示不执行历史迁移。
- [ ] 默认突出 06:00–24:00，两端可展开；凌晨打开和定位“现在”自动使当前时段可见。
- [ ] 用户手动浏览后不抢回；重叠、短时长、跨午夜片段和无时刻内容保持可读。
- [ ] 用已有时间轴、日期投影和 packaged 场景验证边界、来源、展开及定位；在真实窗口检查卡片可读性。

## 03：协作接入生活日与自然语言日期判断

Blocked by: 01（复用统一生活日规则）。

交付：协作默认目标与 Today、习惯一致；输入区显示目标日期，凌晨的“今天／明天”根据上下文理解，最终写入准确日期。

- [ ] 协作上下文包含真实日期时间、生活日和显式目标日期；默认目标采用生活日，用户明确选日期时保留其选择。
- [ ] 对有明确语境的表达推断日期，不按词面机械偏移；明确日期优先，确实含糊且影响写入时才简短澄清。
- [ ] 通过现有确认流程展示具体写入日期，并检查 Tasks、Daily Record 和习惯写入落到对应目标；不改变现有写入权限边界。
- [ ] 进行中请求、草稿与录音的原会话／目标绑定跨午夜、跨 04:00 和切会话仍成立；完成时不使用完成日期覆盖原目标。
- [ ] 已有会话历史和真实时间戳保留，不把历史会话统一迁到新的默认生活日。
- [ ] 服务／受控运行时测试验证上下文和最终写入，不断言模型逐字措辞；真实隔离协作流程验证凌晨指代与确认结果。
- [ ] 本票完成时一并验证 Today、习惯和协作的默认日期一致。无需等待语音控件改版；当前录音绑定保护属于本票回归范围。

## 04：历史习惯入口直接到达补记操作

Blocked by: None (can start immediately).

交付：从习惯历史选定日期后直接到达补记区，清楚显示所选日期，使用与普通习惯一致的完成／撤回交互。

- [ ] 历史日期入口无需用户手动滚到页面底部即可操作补记。
- [ ] 目标日期可见，完成／撤回作用于同一明确日期，刷新后展示一致。
- [ ] 复用现有本地习惯更正链路和身份，不增加第二套存储；外部证据继续只读。
- [ ] 重启、切 Vault、刷新和快速切日期不导致丢失或串写。
- [ ] 以真实 packaged 入口和隔离保存验证补记及撤回闭环。

本票处理显式历史日期，不依赖新的默认生活日；01 负责换日规则的综合接入，避免以共享页面作为虚假阻塞。

## 05：协作辅助栏可收起、调宽并适配窗口

Blocked by: None (can start immediately).

交付：会话历史和当前工作区可独立收起，栏间可拖动调整并记住选择；窄窗口保留可用的主要会话区域，无需整页横向滚动。

- [ ] 保留既有三类内容和工作路径；左右辅助栏可收起及恢复，辅助内容始终可达。
- [ ] 拖动调宽与展开状态可记住，恢复窗口时将保存宽度约束到可用范围，不挤出输入区。
- [ ] 在日常窗口和窄窗口验证阅读、输入、发送、历史选择和当前工作操作不依赖整页横向滚动。
- [ ] 键盘操作、可访问名称、中英文界面和焦点恢复可用；草稿与会话不因布局切换丢失。
- [ ] packaged 窗口实际操作验证拖动、收起、展开、重启及窗口缩放；测试用户行为，不继续锁死旧三栏最小宽度。

## 06：中文／美式英语单语言录音与输入区麦克风

Blocked by: None (can start immediately).

交付：用户在输入区选择中文或美式英语，通过麦克风录音，得到可编辑文字，核对后发送；语言选择被记住，其他英语变体从选项中移除。

- [ ] 两种目标语言与本机识别能力准确对应；不可用时明确提示，不能静默切换另一语言或返回假成功。
- [ ] UI 仅保留所需中文与美式英语选择，记住选择；不删除系统语言资源。
- [ ] 麦克风入口支持开始／停止，取消、录音中、转写中和失败状态明确；输入焦点及键盘操作可用。
- [ ] 转写进入原会话可编辑草稿，不自动发送；权限拒绝、取消、失败、空结果和切会话时已有文字及目标绑定受保护。
- [ ] 真实设备分别完成中文和美式英语录音→转写→编辑→发送；模拟音频只验证状态和错误处理，不代替识别质量验收。
- [ ] 沿用现有离线系统路径，不引入模型、服务或依赖；若目标语言实际不能工作，记录具体限制，不以混合识别研究扩展本票。
- [ ] 验收证据明确覆盖既有 #19 的识别质量缺口；该票不作为先行阻塞，也不在本次拆票时关闭。未来是否关闭 #19 必须以其原验收范围实际满足为准。

新 spec 已明确授权改为麦克风按钮，因此本票按 #28 的新交互要求执行；保留 #19 中原会话、草稿、确认发送和真实录音验收等有效约束。
