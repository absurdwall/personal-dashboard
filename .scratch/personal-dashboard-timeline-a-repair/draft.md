# A 时间轴视觉还原修复 — 已批准的拆分历史

## 来源与事实

用户对已完成的时间轴实现明确不接受，要求依照已确认 A 原型重新开票；不重新设计 prototype。依据本对话提供的 A 原型与正式 App 两张截图，以及当前实现和旧票的结票记录。

- A 的事项在时间轴上以浅色卡片直接显示时间及任务名；正式 App 截图主要显示时间链接与细线，没有直接显示任务名。
- 正式 App 截图两个 13:00 标签相互遮挡；当前渲染把同一开始分钟的链接横移 15px，并不等于按实际标签宽度避让。
- A 的计划／事实有不同底色与边框，“现在”线为红色；正式截图使用不同视觉表达。
- 当前渲染代码的时间链接文本只有开始时刻，正文另放在详情区。这是可核对的实现差别；本轮未启动 App 复现，也未完成运行时根因诊断。
- 旧票 02 已勾选原型对照与重叠可辨识，但本次截图否定其视觉交付结论。保留旧票的执行历史，不以旧票状态作为修复的通过证据。

时间范围需要区分：上一轮票明确要求全天 00:00–24:00 可达，A 的 06:00–23:00 为演示范围。因此全天覆盖本身不是错误；默认可见时间密度、视口、定位行为仍应贴近 A。不得为了截图相似裁掉深夜记录。

## 待批准票 01：恢复 A 的直接可读双栏时间轴

Blocked by: None。

交付：把真实 Daily Record 通过现有应用读取链路呈现为 A 的双栏卡片时间轴；无需点击、悬停或展开详情即可读到普通长度事项的名称和时间。保留现有时间与来源语义。

验收要求：

- 计划左栏、事实右栏、共享等比例时间尺，列标题位置准确；主要内容区与未知时间区保持 A 的层次与相对布局。保留既有产品导航，不要求复制演示控件或整个应用外壳。
- 计划采用浅米色底及虚线边框，事实采用浅绿色底及实线边框，配清楚图例。默认主题以 A 为基准；其他现有主题维持可读性与语义区别。
- 时间和任务名直接出现在有底色的卡片上，详情只能补充信息，不能承担普通事项名称的唯一展示。长文本可合理截断并展开，但不得只剩时间标签。
- 明确起止范围按持续时间表现卡片；单时点仍需有名称与可读标记，不能编造时长。现在用红色细线和可读时刻标签跨两栏定位，不穿过或遮挡主要文字。
- 保留 00:00–24:00 可达，默认使用与 A 接近的小时密度和当前时间附近视口，提供定位现在；定时刷新不抢走手动滚动位置。
- 使用与 A 相同的合成午餐、散步、整理项目资料等数据，固定当前时间 14:10；相同内容视口、字体缩放和滚动位置对照截图，明确普通卡片无需交互即可读名。
- 实施前建立能在当前实现上失败的 rendered UI 回归：普通事项正文必须出现在时间轴卡片可见范围，不能只检查 DOM 有文字或 aria-label 有文字。实施后核对真实 packaged App 截图与 A，逐项列出通过／差异；不以截图文件存在或脚本返回成功替代观察。
- 独立演示 packaged App 真实读取合成 Vault 到卡片的链路，记录构建 SHA 与截图证据；保留时间解析、历史日期、本地习惯更正等已有行为。

## 待批准票 02：让 A 卡片在重叠与窄窗口下保持可读

Blocked by: 01（依赖其卡片结构与几何布局）。

交付：同一时间、相邻时间、持续区间交叉和短事项，在实际双栏卡片界面中都能辨识和操作；窄窗口仍保持 A 的信息层次，而非退回只有时间的标记。

验收要求：

- 明确重现两个 13:00 事项，分别显示可读名称与时间，点击目标独立，不重叠遮挡；同时覆盖 13:00 与 13:05、区间部分重叠、长短事项混排与三项以上密集内容。
- 基于完整可见卡片／标签矩形进行避让，不能只按完全相同分钟或固定小偏移。短事项的最小可读尺寸与真实时长锚点分开表达，不夸大活动时长。
- 现在标签与事项、小时标签不互盖；长文本、中文／英文和键盘焦点均能阅读、进入详情并返回，不靠 hover 才能识别事项。
- 宽窗口和 640×520 窄窗口均验证列标题、卡片名称、未知时间区、滚动与定位现在；可以有受控滚动，但不能把 A 的核心卡片信息隐藏。
- 先建立针对真实渲染的失败证据，再修复；对可见文本、卡片边界和点击目标碰撞做有意义回归。仅 aria 属性、字符串快照或数值分轨测试不足以验收。
- 每个代表场景都有 packaged App 截图与人工视觉检查记录；用相同数据／窗口说明结果，保留失败前截图。实现者自检后应完成独立视觉复核；对外报告候选待用户验收，不把自动化通过写成用户认可。

## 共同边界与完成门槛

修复现有时间轴，不重建解析／存储，不重做已完成的历史习惯票，不新增服务或依赖，不操作真实个人数据。所有复现使用隔离合成 Vault；不得替换日常 App 或推送。宽／窄和中英文视觉证据须检查实际可见内容，不只是保存截图。

每票均包含自己的端到端检查；不另设末尾才补视觉验证的票。A 为最终参考，不重新发起设计选型。旧父票保持原记录，新票发布后通过新 map 明确视觉修复未完成。
