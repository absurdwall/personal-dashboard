# Personal Dashboard 4.0 — 现有界面内的 Tasks 原型

这版原型专门验证一件事：在当前 Personal Dashboard 的左侧导航中加入一个 `任务` 入口，并让它和现有 Today、Calendar、Habits 共用一套合成任务状态。它直接复用当前生产界面的 workspace HTML/CSS 基线，不另画一套 Dashboard 外壳。

它不是生产实现、不是 Tauri acceptance，也不读取真实 Vault、Dida365、MCP 或自动化。

## 打开

在当前项目根目录运行：

```sh
npm run prototype:dashboard-4
```

服务器默认让操作系统选择一个未占用的 `127.0.0.1` 端口，并在终端打印完整 URL；也可以指定端口：

```sh
PERSONAL_DASHBOARD_4_PORT=4180 npm run prototype:dashboard-4
```

本轮当前运行地址：

`http://127.0.0.1:62008/?screen=today&variant=B&lang=zh&date=2026-09-19&month=2026-09`

左侧导航顺序为 `今天`、`任务`、`日历`、`习惯`。刷新页面会重置合成状态。

## 原型范围

- 保留当前 Personal Dashboard 的 toolbar、左侧 workspace 导航、Today 三阶段、Calendar 月视图和 Habits 快照布局；新增的只有 Tasks destination。
- Tasks 是独立的内存对象：名称必填、内容可空、日期和时间可选、单层清单；可新增、编辑、完成／重开、放弃／恢复、删除／撤销和改期。
- Tasks 内左侧同时提供 `今日` smart view 和 `收集箱`：`今日` 按任务日期自动汇总，不是一个可归属任务的清单；`收集箱` 是未指定其他清单时的新任务默认归属。
- 新建任务会跟随入口设默认清单：从普通清单进入就默认选中该清单，从 `今日`、`收集箱` 或全局入口进入则默认选中 `收集箱`。
- Today 继续在右侧显示当天任务；Calendar 月格显示少量任务和 `+N`，选中日期显示 Review 与完整任务列表；三处引用同一条任务身份。
- Calendar 在较窄窗口下保留每个日期最多两条短任务摘要，再用 `+N` 表示其余任务；极窄时单行省略，完整任务名仍在选中日期的详情面板中。
- Calendar 固定按 Task date 放置。示例“9 月 17 日的洗衣服在 9 月 19 日完成”仍留在 9 月 17 日，并单独显示实际完成时间；只有显式改期才移动。
- 归档的「8 月其他」清单含未完成任务：不出现在 Today 的日常待办，但可从 Tasks 归档入口和历史 Calendar 查到；恢复清单不会批量改变任务状态。
- Habits 沿用当前紧凑布局，展示中英名称与缺少译名时的原名回退；不创建新习惯或目标。

## 合成 fixture 日期

演示今天固定为 `2026-09-19`，当前月为 `2026-09`，可向前查看 `2026-08`：

- `2026-09-19`：Today，包含已完成、待办和临时任务。
- `2026-09-17`：晚完成示例；任务日期为 9 月 17 日，实际于 9 月 19 日完成。
- `2026-09-12`：逾期未完成任务。
- `2026-09-06`：拥挤日期，月格展示 `+N`。
- `2026-09-22`、`2026-09-24`：未来任务，其中部分没有 Daily Record。
- `2026-08-28`、`2026-08-29`：归档清单中仍有未完成任务。

## 本轮纠偏决定

- 以 `frontend/index.html` 和 `frontend/styles.css` 为视觉基线；不重做全局 shell，不引入另一套 sidebar、toolbar 或 Today 排版。
- Tasks 放在现有左侧导航的 Today 之后，使用现有 workspace destination 切换方式。
- Tasks 内的 `今日` 是自动视图，和承载默认新任务的 `收集箱` 分开；普通清单的新建入口保留当前清单作为默认归属。
- Calendar 只做窄窗口减密，不改变现有月视图和右侧详情结构。
- `variant=A|B|C` 只保留为 URL 兼容参数，用于月格任务预览密度；不再切换三套全局布局，也不显示会造成误解的悬浮切换条。
- 所有状态只在浏览器内存中；满意后再由用户决定是否捕获到 throwaway 分支并进入正式 spec。

## 限制

- 不验证 Vault 正本、受保护写入、重启恢复、并发冲突、真实早晚流程、Dida365 去重或 packaged Mac 行为。
- 这是用于确认“在现有界面加 Tasks”是否正确的可运行草图，不应直接提升到生产。
