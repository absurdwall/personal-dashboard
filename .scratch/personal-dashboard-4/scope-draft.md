## 已确认的大体框架（具体交互建议仍待细化）

### Task 模块

- 将 3.0 的 Day task 扩展为可独立保存、跨日追踪的 Task。Tasks、Today、Calendar 是同一任务的不同视图；身份不随名称或日期变化。
- 名称必填、内容可空为建议；用户已确认只有一个可选日期／时刻，不拆成安排时间与截止时间。支持无日期、仅日期、日期加时刻，以简单任务时间体验为准。
- 支持新增、编辑、完成／撤销、删除、手动改期。单层清单／分类作为首版建议，暂不引入嵌套文件夹。
- 细化确认：支持显式“放弃”，与完成、删除区分，保留历史；归档清单退出日常待办，不自动改变其中任务状态。晚完成不改变 Calendar 任务日期；明确改期才移动位置。
- 建议提供全部、今天、未安排、逾期、已完成等必要视图；具体数量通过原型确定。
- 未完成任务继续可查；逾期保留原日期，不自动修改成今天。未勾选仍表示完成未确认，不能直接作为没做的事实。
- 用户说明 3.0 刚交付，尚无需要继承的实际任务积累；旧任务迁移不作为本轮主线或独立功能要求。此为用户使用情况说明，未扫描实际任务文件，也不授权删除旧数据。技术上 3.0 已有按日保存及历史更正，但尚无 4.0 的独立跨日任务管理；不能将两者混同。
- 逾期与已完成任务可查看，完成可撤销。历史月份应能看到当时的任务及完成标记；清单归档后历史仍可查，归档不等于删除。归档入口、恢复操作和完成划线样式留待具体设计。
- 保存、重启、改期、跨视图更新、切换 Vault、并发冲突构成“稳定”的交付要求。继续沿用 Vault 正本、受保护写入和用户内容保留机制。

### Calendar 集成

- 月格上部显示现有 Review 状态；保留无记录、未复盘、已复盘、读取错误的区别。
- 下部建议显示 2–3 条任务，超出显示 `+N`。数量由窗口大小与原型体验决定。
- 用户已确认：点击 `+N` 或日期均选中该日，在现有右侧面板显示完整任务，不增加浮窗。
- 右侧提供完整任务、操作入口及现有 Daily Record 阅读入口；保留历史复盘浏览能力。
- 无日期任务仅出现在 Tasks 对应视图，不硬塞入某一天；有未来任务但无 Daily Record 的日期也应能显示任务。
- Review 是日期状态，不变成需要打勾的任务。Calendar 浏览不得创建空日记。
- 历史已完成任务保留可查，以划线等方式表达完成；按 Task date 归位，右侧承接完整任务与编辑入口。

### Habit 双语名称

- 同一个稳定 Habit key 对应两种显示名，切语言只切名称，历史完成记录不复制、不重置。
- 缺少另一语言时建议回退原名，避免空白；双语名称随 Vault 保存，具体存储与外部快照兼容方式待定。
- 本次需求显式扩大 3.0“habit names 保持原文”的显示边界；任务正文、日记、来源记录仍不自动翻译。
- 用户已确认创建 Habit／修改目标排入 4.1，属于同一轮 4.x 迭代，但不作为 4.0 首次交付内容。

## 本轮后续确认

1. Task 只有一个可选日期／时刻，不增加两套时间字段。
2. 4.0 做 Habit 名称双语；创建 Habit 与修改目标排入 4.1，仍在本轮迭代规划内。
3. 4.0 纳入真实早间规划／晚间复盘与 Dashboard 任务接线，用户接受上一轮建议。既有滴答任务的迁移范围尚未决定，不据此执行全面迁移或停用滴答。
4. 用户要求先展示旧 checklist 原文及出处，方便确认找对了资料，再继续范围收敛。原勾选状态应保留，历史状态与当前核对结论分开。
5. 2026-09-17 用户确认大体框架：无日期任务、逾期／完成可查和撤销完成、历史 Calendar 与归档后可查、Tasks／Today／Calendar 一致。当前先定框架，不继续扩展为实现或细节访谈。
6. 3.0 实施 tickets 已完成；本次提及“旧任务”指用户的生活 Task，不是未完成开发票。用户说明无需继承实际旧任务，迁移退出主线。
7. Q1–Q3 已确认：晚完成不改变任务日期；归档后退出日常待办而保留状态与历史，支持显式放弃；过渡期早晚流程读两边，新建任务写 Dashboard，滴答仅作有来源的参考，不自动复制或写回。
8. Q4–Q5 已回答：Agent 改期优先建议、等确认；明确表达且可可靠匹配的意图可直接执行。用户明确完成／放弃可直接更新 Dashboard 任务；含糊或冲突时再问，不推断完成，也不虚构补记的实际时刻。

## 建议推进顺序

当前停在大体框架已确认。后续再细化 Tasks 与 Calendar 交互、制作独立可体验原型；认可后写正式规格和任务拆分。规格需覆盖未来日期、无日期、历史／归档可查、持久化／并发、三视图一致性、Habit 名称回退，以及真实 packaged Mac 的视觉与操作验收。早晚流程接线已纳入，真实流程验证与合成测试分开记录；旧数据保持非破坏，不单列迁移工程。

本轮仅创建此设计草案；未修改产品代码、skill、真实任务／Habit／日记或自动化，未调用滴答，也未重跑旧验收。
