Part of #116 — PDBETA-SPEC-01：Personal Dashboard 首次受邀 Beta 发布。

## What to build

把全部完成并合并的准备工作构建为最终候选，在全新 macOS 用户上完成真实安装和使用验收；整理包、网页、手册和证据供审阅。获得针对具体候选与公开内容的发布授权后，启用本仓库 Pages，并创建对应的 GitHub prerelease、DMG 和校验和，完成匿名下载验证。

首轮邀请少量 Apple Silicon Mac 用户，但公开网页/资产不限制非受邀者访问。规格和实施票的批准不等同于最终公开发布批准，不发送测试邀请。

## Acceptance criteria

- [ ] 最终源码、发行声明、App、DMG、SHA-256 和文档一致，记录版本/build、系统/架构和外部 Codex。必要回归检查通过；包发生变化后重新绑定哈希并重做受影响验证。
- [ ] 全新 macOS 用户无维护者环境，实际挂载 DMG、复制到 Applications、推出 DMG、经过最终包对应的 Gatekeeper 流程启动，确认运行的是复制品。临时 HOME、开发机隔离或静态签名检查不能替代此证据。
- [ ] 按教学创建空白个人空间，完成本地 Task/Habit/记录的保存和退出重启读回；按文档自行安装外部 Codex、登录自己的 ChatGPT，完成真实 AI 修改、语音转写与自动安排。实际业务来源独立读回，不把模型回复当作保存成功。
- [ ] 检查无依赖/未登录/断网时的本地可用性、真实编辑冲突、草稿与原文保留、备份恢复、由内部版本替换安装和稳定身份；记录最低系统支持证据及未覆盖范围，不承诺任意降级。
- [ ] 不建设新滴答接入、不引入内附 Codex、Developer ID/公证服务、后台自动启动或本轮外功能；发现问题在已批准范围内修复并复验，范围外问题另行报告，不无限扩票。
- [ ] 发布前呈现具体最终包、网页/手册、限制、实际验收结果与未执行项，并取得针对这些结果的公开发布授权。所有工程和部署配置变更按项目 PR 规则处理，不直接改主分支。
- [ ] 获准后创建明确 tag 的 prerelease、DMG、SHA-256 和发行说明，并启用同仓库 Pages；不改变仓库可见性、不引入新服务、不发送邀请。公开用户下载入口只在必要检查完成后开启。
- [ ] 用匿名浏览器下载实际公开资产，核对校验和，并验证真实下载带隔离标记的首次安装/打开流程；页面、版本、资产和手册一致。若失败，纠正或暂撤错误下载入口并准确报告，不声称发布通过。
- [ ] 发布记录清楚区分通过、失败、未执行和用户报告；本轮验收材料与恢复备份保留，按项目规则处理构建缓存/临时 App 注册，并刷新 Management 已登记的 GitHub 来源。

## Scope and handoff

前置票交付的包或文档不是自动通过证据。先完成本票可自行完成的准备和验证，再让用户审阅具体发布结果；需要人工的账号登录或干净用户步骤保持明确。发布完成后以真实 URL、最终哈希和验收记录交付，未完成项不得通过关闭票据消失。
