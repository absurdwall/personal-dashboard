# PDBETA-SPEC-01：Personal Dashboard 首次受邀 Beta 发布

日期：2026-10-17（America/New_York）。这是首次对外 beta 的规格；发布规格不代表功能实现、安装验收或公开下载已完成。GitHub Issue 是发布后的唯一活动规格，本文保留同步副本。当前工程基线为 `9e8132b96a6669259d34981fcb602c48774efaf8` / `4.0.7`。

## Problem Statement

Personal Dashboard 已有可安装的 Mac App，以及 Tasks、Today、Calendar、Habits 和 Codex Collaboration，但当前交付围绕维护者自己的电脑和 Vault。其他用户缺少可信的产品说明、可下载的 DMG、创建个人数据的路径，以及安装、首次登录和日常使用手册。现有 README 仍主要描述历史 2.0，不能作为当前用户说明。

维护者希望先邀请少量 Apple Silicon Mac 用户，包括 AI 协作在内，实际使用并反馈。不能把开发机能启动、历史测试通过或 Bridge 已发布，作为陌生用户能安装和使用本产品的证据。

## Solution

在现有公开仓库中准备一套一致的 beta 交付：中英介绍与下载网页、版本明确的 GitHub prerelease、DMG 和 SHA-256、安装与首次使用指南、完整手册，以及互相链接的 README。页面结构借鉴 Bridge；所有功能、运行依赖和支持范围以 Personal Dashboard 最终包的证据为准。

首轮测试对象为少量受邀的 Apple Silicon Mac 用户，AI 协作属于本轮验证范围。源码继续公开，复用同一仓库 Pages 与 Releases。网页和下载资产若公开，非受邀者也能访问；邀请是测试组织方式，不是访问控制。

先补齐新用户初始化和外部 Codex 的使用路径，再完成最终包的真实首次使用验证，最后依据明确授权开放下载。首个公开版本显示为 `1.0.0 Beta 1`，发行标签为 `v1.0.0-beta.1`；沿用 Bridge 的本地签名、未公证路线。Codex 由需要 AI 的用户自行安装，用户在 Dashboard 设置中登录自己的 ChatGPT。安装包不内附 Codex 程序。规格与 GitHub Issue 的发布不自动启动实施或发布 DMG。

## User Stories

1. 作为受邀测试用户，我希望快速理解产品适合什么日常管理场景，以决定是否试用。
2. 作为测试用户，我希望看到来自合成数据的真实产品截图，以了解实际功能而不接触维护者私人信息。
3. 作为中文或英文用户，我希望网页与固定界面文案支持两种语言，以理解操作而不改写自己的记录。
4. 作为 Mac 用户，我希望下载前知道支持的芯片、系统和 AI 要求，以避免下载无法使用的包。
5. 作为 Intel Mac 用户，我希望明确看到首轮尚不支持的范围，以免把 Apple Silicon 包当作通用包。
6. 作为测试用户，我希望下载链接指向明确版本，以核对版本说明和故障报告。
7. 作为测试用户，我希望获得 SHA-256 和签名、公证状态，以核对下载资产及其来源信息。
8. 作为首次安装者，我希望知道打开 DMG、拖入应用程序、推出 DMG 后再启动的顺序，以免一直运行挂载盘中的副本。
9. 作为被 macOS 拦截的用户，我希望看到适用于这个包的具体首次打开流程，以完成安装。
10. 作为设备受管理或遇到损坏提示的用户，我希望有明确的排查和反馈路径，以避免反复执行无效放行操作。
11. 作为新用户，我希望在不复制维护者 Vault、不安装开发工具的情况下创建自己的数据目录，以开始使用本地功能。
12. 作为已有兼容 Vault 的用户，我希望明确选择已有目录，以保留原内容和数据所有权。
13. 作为普通文件夹或不兼容 Vault 的使用者，我希望理解原因和可选路径，以避免静默转换已有资料。
14. 作为新用户，我希望能新建首个 Task、Habit 和一句记录，以验证产品无需预先准备个人历史。
15. 作为 Task 用户，我希望 Tasks、Today 和 Calendar 展示同一 Task，以避免重复数据和完成状态分裂。
16. 作为 Habit 用户，我希望理解目标、完成天数和本地/外部证据的区别，以正确解释统计。
17. 作为 Daily Record 用户，我希望知道何时会创建记录、如何规划及复盘，以区分计划与实际活动。
18. 作为跨午夜使用者，我希望知道 lived day 的 04:00 边界，以理解记录所属日期。
19. 作为断网用户，我希望本地 Task、Habit 和记录仍可使用，以持续维护自己的资料。
20. 作为 AI 用户，我希望网页或 README 说明如何自行安装兼容的 Codex 及准备自己的 ChatGPT 账号，以按说明启用 Dashboard AI。
21. 作为 AI 用户，我希望在 App 内使用自己的 ChatGPT 账号完成连接，以独立使用协作功能。
22. 作为已有 ChatGPT 登录的用户，我希望知道 Dashboard 的连接是否需要单独登录，以免误以为已有会话必然被继承。
23. 作为账号权限不足、额度耗尽或运行时不兼容的用户，我希望得到明确状态和恢复指引，以继续使用可用部分。
24. 作为 AI 用户，我希望了解哪些本地内容和语音会用于在线处理，以决定是否发送。
25. 作为协作用户，我希望看到实际修改、失败与恢复结果，并可在数据中读回，以区分回复成功和保存成功。
26. 作为语音用户，我希望麦克风按需请求权限，转写可编辑并由我发送，以控制输入内容。
27. 作为不使用滴答的用户，我希望本地功能和本地 AI 协作不以滴答账号为前提，以独立使用产品。
28. 作为已有滴答接入的用户，我希望 beta 发布保留我的现有能力，以免首次对外发布破坏已有使用；新用户无需配置滴答。
29. 作为使用云盘的用户，我希望理解本地目录与桌面同步客户端的边界，以免把本地保存当作云端同步完成。
30. 作为用户，我希望退出、重新启动后读回自己的修改，以确认持久化。
31. 作为与外部编辑器共同使用 Vault 的用户，我希望冲突时保留草稿与已有内容，以安全恢复。
32. 作为升级用户，我希望替换 App 后自己的数据和设置被保留，以持续使用相同个人空间。
33. 作为用户，我希望手册说明个人资料的备份、恢复与卸载保留边界，以避免把重装当作数据恢复。
34. 作为反馈者，我希望知道应报告的版本、系统、复现步骤及脱敏方法，以提供有用反馈而不公开私人记录。
35. 作为维护者，我希望网页、App、DMG、Release 与手册的版本和功能声明一致，以避免错包或过时说明。
36. 作为维护者，我希望每个支持声明都有最终发行包的验收记录，以诚实说明已知限制。

## Implementation Decisions

### 已确认的产品与公开范围

- 用户已确认少量受邀的 Apple Silicon Mac 用户，包含 AI 协作；源码保持公开，复用现有仓库网页和 Release。
- 保留现有 Tauri、Rust、TypeScript 和本地文件持久化边界。复用已有打包能力，优先不增加依赖、外部服务或新仓库。
- 产品定位为本地优先的个人管理 App，包含有条件使用的在线 AI；不再用“整个产品完全离线”描述所有功能。
- 本地功能不以滴答、云盘或 AI 账号为前提。语音转写、Collaboration 和自动早间安排需要相应 AI 条件；没有这些条件时，本地 Tasks、Habits 和 Daily Record 仍可使用。
- 首轮不建设面向新用户的滴答接入流程，也不要求用户配置滴答。保留维护者已有可选接入能力；不因本次 beta 删除或重做它。云同步继续由用户选择的桌面客户端承担。
- 保留应用身份和现有用户资料位置，避免因首次公开发布而重置维护者或已有用户的数据。

### 新用户开始使用

- 在现有 Vault 选择和业务持久化接口上提供清晰的“新建个人空间”和“选择已有兼容 Vault”路径。新建时用户只需选择位置、命名文件夹；App 自动准备最小必要结构，不要求用户手建子文件夹，不带入维护者数据、个人技能或账号，也不预装演示任务和日记。
- 不要求用户事先安装 Obsidian 才能运行 Dashboard。若保留兼容标记结构，应解释这是数据格式兼容性，不是外部 App 运行依赖；最终行为需随初始化方案验证。
- 非空、不兼容、只读或不可用的目录给出明确结果；不自动搬迁、重写或转换其用户内容。迁移和覆盖需要独立明确指令。
- 空历史是正常状态。仅在用户实际保存时创建对应 Task、Habit 或最小 Daily Record；浏览日期不制造记录或完成事实。
- 长期背景和日常工作流参考缺失时，应明确其状态；首用不得依赖维护者的个人背景文档或外部技能安装。若要提供可选背景模板，只能使用合成、通用内容，并作为明确产品行为实现。
- 中英文使用中性产品术语，移除正常用户流程中要求维护者专用 Vault 的措辞，保留已有 Daily Record/Task/Habit 语义。

### AI、语音和可选集成

- 用户已确认沿用外部 Codex 路线：需要 AI 的用户自行安装兼容的 Codex，并在 Dashboard 设置中登录自己的 ChatGPT。Dashboard 已有 App Server 连接代码；所调用的 Codex 可执行程序来自用户电脑。安装包不内附、自动下载或代用户安装 Codex，不内附完整 Codex/ChatGPT 客户端，更不包含开发者账号、订阅或凭证。
- Codex 安装和 AI 准备步骤可以由 README、网页和手册引导；不要求新增 App 内安装向导。App 保留清楚的连接状态、兼容性检查和失败提示，让用户知道应按文档采取什么行动。
- 发布前必须验证普通用户能通过文档获得的兼容运行时。说明准确区分 Codex 可执行程序、客户端 App 和 ChatGPT 账号；不能只承诺“装了任何 Codex App 就一定可用”。查找和候选选择应可靠处理 GUI 启动环境、旧版本及不可用候选，仅探测到文件或版本号不等于可用。
- Dashboard 使用应用专属账号资料，不保证继承其他客户端的登录。用户自己的账号、网络和服务权限由用户准备；产品仍负责其连接代码、兼容性判断、状态反馈和记录持久化。
- 无兼容运行时、未登录、断网、无模型权限或服务失败时，提供可恢复说明；本地功能继续可用。AI 的可用账号、模型及限制以实际发现和服务状态为准，不承诺所有 ChatGPT 账号都可用。
- AI 登录、数据传输和语音说明必须对应实际集成。语音是在线转写至可编辑草稿，由用户发送，不宣传为离线或实时语音对话。
- 继续遵循现有 Codex 对用户意图的解释及 Dashboard 机械持久化约束；不因 beta 新增第二套自然语言授权拦截层。
- 首轮网页和快速开始不把滴答作为必备或主要卖点；手册只需清楚注明可选现有集成的边界。没有接入时不得阻止本地或本地 AI 使用，不新增滴答一键配置，不在公开说明中复制个人端点或凭证。
- 语音转写和自动早间安排保留并纳入首轮验收。自动安排沿用现有进程内调度，只在 App 运行时工作，彻底退出后不自动执行；不新增开机启动、常驻后台服务或自动唤醒。手册准确说明默认关闭、用户主动启用、App 运行/休眠/退出及失败条件，不宣传后台必达。首次使用不能让没有旧日程的新用户为维护者自己的历史调度做不适用的交接；已有调度仍应避免重复执行。

### 版本、包与签名

- 用户已选定首次公开版本显示为 `1.0.0 Beta 1`，发行标签为 `v1.0.0-beta.1`；不再采用先前建议的 `4.1.0-beta.1`。当前 `4.0.7` 是实施起点，规格修改本身不改变 App 或工程版本。
- 发行实现统一展示版本、系统数值版本和递增 build 的映射，并验证由内部 `4.0.7` 替换安装时的资料保留和身份延续。每个重新分发的构建都可区分；不另建应用身份规避版本或数据兼容问题。
- 建立唯一发行声明，统一展示名、数值版本、build、tag、架构、最低系统、资产名称和源码提交。最终 DMG 的每次内容变化都必须有可识别的新构建，不用旧哈希替代。
- 首轮分发 Apple Silicon 包，不承诺 Intel、Universal、Windows 或移动端。最低 macOS 要求待主程序、AI 运行时及实际 API 的约束和最低系统验收共同确定；当前配置中的 12.0 不是已验证支持声明。
- 优先复用 Tauri 原生 DMG，含 App 与 Applications 拖放入口；最终包可只读挂载核验，校验文件指向实际分发字节。
- 用户已确认首轮采用与 Bridge 相同的本地签名（ad-hoc）且未公证路线；Developer ID、公证和 staple 不是首轮交付门槛，也不在本轮新增相应账户/服务配置。不得声称已有 Apple 验证的开发者身份或已公证。
- 安装指南提供 Apple 当前支持的针对单个 App 放行流程：先尝试打开，再进入系统设置的隐私与安全，按可见的“仍要打开”和后续确认操作；并完成真实下载资产的实测。受管设备及损坏/恶意软件提示单列排查；不要求关闭全局 Gatekeeper。
- SHA-256 用于字节一致性核验，不代替开发者签名或来源信任。

### 网页、README、手册与发行

- 网页按“产品用途 → 实际功能和截图 → 要求 → 明确版本下载 → 安装与首用 → 手册/已知限制 → 反馈”组织，支持中英切换；参考 Bridge 的流程，不改 Bridge 项目或复制其产品能力声明。
- README 提供简明产品入口、要求和快速开始，链接网页、安装指南、完整手册与版本说明；开发者构建说明与用户安装说明清楚区分。历史验收记录保留为历史，不整体覆盖重写。
- 手册覆盖创建/选择个人空间、Tasks、Today、Calendar、Habits、Collaboration、语音、可选滴答、04:00 lived day、资料位置、同步边界、备份恢复、升级卸载和故障反馈。
- 公开截图与样例只能使用专门构造的合成资料；包、站点、手册与示例不得包含个人 Vault、登录凭证、聊天记录、账号标识、个人绝对路径或测试残留。依赖的公开许可证与致谢随实际包提供。
- Release 采用 prerelease，并以明确 tag 链接 DMG、校验和与发行说明；beta 下载不依赖可能跳过 prerelease 的 latest 链接。不得把大型 DMG 提交进网站源码目录。
- Pages 配置、发行 tag 和 Release 资产是实际公开发布动作，在具体候选内容、最终包和必要验证结果可审阅后执行；规格 Issue 的创建只发布规格。发布网页不得展示尚不存在或未获准开放的下载入口。
- 所有工程和文档改动走 `codex/` 分支和受保护主分支的 PR；不直接写主分支。公开 GitHub Issue 不自动授权实施、合并、修改部署配置或向测试者发消息。
- 控制并记录构建缓存占用；结束时只清理明确可重建且属于本次工作的产物，保留验收材料、用户资料和恢复备份。临时 App 位于不索引目录并解除多余注册，正式可搜索安装继续只有一份。

## Testing Decisions

用户已确认主验收链：“全新 macOS 用户下载 DMG → 安装并推出 DMG → 初始化个人数据 → 自己登录 AI → 保存后重启读回”，补充断网、冲突与升级。

- 优先复用现有应用命令/业务接口、前端流程测试和 packaged acceptance 工具。主验收对象是最终分发 DMG 的用户行为；不新增替代真实安装的模拟接口。
- 好的测试观察用户结果：用户能创建资料、可见失败、保存后真正读回、退出重开后保留、外部原文不丢失。测试不得只是重述内部实现；模拟麦克风或模型测试只能作为支持证据。
- 初始化：全新 macOS 账号，无维护者环境和历史；分别验证新建空空间、选择已有兼容 Vault、取消选择、非空不兼容、只读及目录消失。检查没有个人资料或意外转换。
- 本地闭环：创建并编辑 Task、在 Today/Calendar 读回同一对象；创建 Habit 并完成/撤销；首次保存一句记录创建最小 Daily Record；退出重启后逐项读取同一来源。断网及未登录 AI 时重复关键本地流程。
- AI 闭环：按最终公布路径准备普通用户运行时，自己登录；确认实际运行时和可用模型；从聊天执行一项合成数据修改，独立从业务页面和文件读回。测试运行时缺失/不兼容、登录取消、网络/服务失败，保留草稿和已确认结果。
- 语音和自动安排：使用真实麦克风验证授权、转写到可编辑草稿、手动发送、停止/取消、导航与退出边界；验证中文、英文和中英混合。以新建个人空间和用户自己的 AI 连接验证默认关闭、主动启用后的计划保存与读回、进程运行/退出及失败状态；重复检查不产生重复计划。未运行的识别质量与持续时长测试不得写成已通过。
- 滴答边界：未配置时验证本地功能、AI、语音和自动安排不被无关接入阻止。保留现有接入回归覆盖，不新增测试者滴答开户/接入的验收门槛，不借用维护者个人账户验收。
- 持久化与恢复：与外部编辑器形成真实冲突，验证内容与草稿保留；在用户私有的合成数据副本上演练手册中的备份/恢复，不把旧版已退休备份模块当作当前产品功能。
- 安装链：签名结构、架构、最低系统元数据、内附资源/依赖与许可证；真实浏览器下载的隔离资产；复制至 Applications、推出 DMG、通过最终包对应的 Gatekeeper 流程后运行，确认进程来自复制品。临时 HOME/同账号隔离不能代替全新用户测试。
- 升级：从明确指定的前一候选替换 App，验证稳定身份、个人数据/设置及会话的实际保留；若无前一公开 beta，记录现有安装的合成资料升级证据和首发边界，不伪造公开版本历史。恢复旧包前先确认格式兼容，不承诺任意降级。
- 文档/站点：匿名访问页面、DMG 和校验和；校验实际资产字节；检查中英切换、桌面/窄屏、互链、版本/要求/限制一致和截图脱敏。预先验证候选包，发布后再做匿名实际资产验证；公开入口只在必要检查完成后开启。
- 每份验收记录绑定源码提交、发行身份、最终 App/DMG 哈希、系统/架构和运行时；分别记录通过、失败、未执行与用户报告。历史文档和开发者机器结果不得补齐本轮空白。

## Out of Scope

- 首轮 Intel/Universal、Windows、iPad、Android 或手机端交付。
- 自动更新系统、App Store 发布、遥测/分析后端、额外云服务或新的 AI/同步平台。
- 产品内 Google 账号登录和 App 自管的 Vault 云同步；整个个人知识库的迁移或大规模重组。
- 把滴答作为必需账号、面向新用户的新滴答接入流程、自动导入所有外部任务/习惯、任意第三方 MCP 配置器或完整客户端替代。
- 内附、自动下载或代用户安装 Codex；新增 Codex/ChatGPT 客户端安装向导；提供用户的 ChatGPT 账号、订阅或额度。
- 本轮 Developer ID/公证服务配置，以及开机启动、App 退出后的后台自动安排或自动唤醒。
- 实时语音对话、离线语音回退或未核实的全部账号/模型支持。
- 重启已关闭、延后或退休的历史票，以及与 beta 首次使用无关的全面视觉重设计。
- 在规划阶段直接改当前工程版本或安装版、改变仓库可见性、现在就启用 Pages 或发布可下载 Release，以及发送测试邀请。经批准的发行实施包含选定的首次公开版本，不再把版本调整本身排除在后续交付之外。

## Further Notes

### 事实、决定与建议

- **当前事实**：仓库已经公开；尚无 Release，匿名 API 显示未启用 Pages。工程为 4.0.7，仅配置 App 打包；本机正式 App 是 arm64/ad-hoc，最低系统元数据 12.0。上述为本轮读取，不是他机验收。
- **当前事实**：已有兼容 Vault 要求特定目录标记；选择器不创建空空间。Daily Record 缺失时，显式保存一句记录可以创建最小记录；不能误写为所有日记必须依赖外部早间流程。
- **当前事实**：Codex 目前从外部发现，应用保存独立连接资料并检查实验协议能力；滴答从现有用户配置发现，可选。长期背景和日常流程参考有维护者工作区约定，需纳入首用处理。
- **已确认**：受邀小范围、Apple Silicon 首轮、包含 AI；源码保持公开并复用本仓库网页与 Release；上述真实安装/重启读回主验收链；`1.0.0 Beta 1` / `v1.0.0-beta.1`；本地签名且未公证；用户自行安装兼容 Codex，并在 Dashboard 登录自己的 ChatGPT；安装包不内附 Codex；README/网页可承担安装说明；用户只选位置/命名，App 创建空白个人空间的必要结构；不需 Obsidian，不预装演示资料；保留语音和仅在 App 运行期间执行的自动早间安排；不建设首轮新用户滴答接入。
- **已调查但尚未完成端到端验收**：Bridge 官方固定候选 `0.156.1`、本机 npm 独立 CLI `0.160.0` 与 ChatGPT 内附 CLI `0.162.0-alpha.17.2` 都在独立临时配置、工作目录和最小环境下成功生成实验 schema，三组参数通过 Dashboard 当前协议字段检查。未启动登录/模型/语音服务，没有读取账号凭证；这只证明本地协议声明兼容，不能写成完整 AI 或陌生用户安装通过。本轮选择外部运行时，未将任一程序复制进安装包。
- **待工程核实**：最终最低 macOS 与具体对外支持的 Codex 安装来源/版本；数值版本与递增 build 的技术映射和替换安装结果。它们需要实际证据，不需要重新询问已确认的产品取舍。没有尚待用户选择的版本系列、签名或 Codex 分发路线。
- 按官方 OpenAI 文档，目前本地或开源应用可继续使用 app-server 认证，官方建议迁移 Sign in with ChatGPT；商业/托管服务的认证用途另有限定。本规格只覆盖当前本地 beta，不据此推出商业授权或迁移承诺。
