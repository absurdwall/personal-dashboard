# 02: 当日时间刻度与现在记录边界

Type: task
Status: needs-triage
Blocked by: None（待分诊）

## 用户反馈

在“今天”中，安排和“当日情况”主要按上午／中午／下午／晚上划分。用户希望“当日情况”能更细到几点几分。

白天打开页面时，用户希望通过“现在”的记录边界线，一眼知道当前处在一天中的什么位置；目前这条线的位置经常感觉不准确，与内容割裂，缺乏完整、连续的时间感。

## 期望行为

- 当日情况提供明确的具体时间参照，能够理解事情发生在几点、先后如何。
- 当前时间线与时间刻度、当天内容处于同一套可理解的时间关系中，让人能直观看出已经过去的部分与后续时段。
- 上午／中午／下午／晚上可以作为分组参考，不能成为判断当前时刻的唯一依据。

## 下轮核查与验收方向（待细化）

- [ ] 在上午、中午、下午、晚上及跨午夜场景检查当前时间线的位置与更新行为，并核对应用采用的日期／时区。
- [ ] 用含明确时间、只有时段、没有时间的合成记录检查时间表达；不为缺少时间的事实编造精确时刻。
- [ ] 明确有时间事件、粗粒度内容与当前时间线的布局关系，验证内容多寡不会造成误导性的位置感。
- [ ] 通过实际界面确认：用户能读出当前几点、当日在何处、已记录内容与当前时刻的关系。

## 已确认设计与待细化边界

2026-09-23 用户已选择 A 原型，不再迭代布局：

- 左侧计划安排，右侧已发生／已确认，共享纵向连续时间刻度。
- 事项的位置与长度表达明确的时间及持续时长；“现在”线按实际当前时间定位，支持定位现在。
- 只有时段或缺少具体时间的内容独立呈现，不虚构精确时间。
- 计划不会因时间经过而自动变成已完成事实。

下一步仅细化可执行 ticket：时间范围与跨午夜处理、真实数据映射、重叠／短事项、窄窗口与验收条件。原型的 06:00–23:00 是演示范围，不能据此遗漏深夜数据；模拟时间滑块是演示控件。无需重新选择 A／B／C。
