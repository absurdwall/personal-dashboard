## 1. 跨午夜后的“今天”与记录归属

- 用户经常在午夜之后仍处于前一天的生活收尾阶段；按零点换日后，记录容易落到第二天，补记变困难。协作更新也有时会把所述内容理解为第二天的内容。
- 希望考虑调整页面的换日／刷新时间，让午夜后的一段时间仍能方便地记录刚结束的生活日。
- 具体换日时刻尚未决定。下一轮需区分页面默认日期、习惯记录归属、协作所用日期上下文与 Today 时间轴范围；不能只改刷新时间就认为问题全部解决。
- 用户也提到凌晨 1 点是否可以仍算前一天。这是待讨论的生活日边界，不是已批准的数据迁移或全局日期规则。

## 2. 历史习惯补记：已有功能，入口与操作体验待改善

- 用户最初以为没有历史更正；谈话中确认已有入口：选择日历中的一天，可“查看并补记它的本地习惯完成”，但进入后还要拉到页面最底下的历史更正部分。
- 因此本项不是新增一个不存在的补记能力，而是让已有历史补记更容易找到、到达和使用。
- 用户感觉历史更正不如普通习惯界面顺手；希望后续考虑接近日常习惯记录的体验。最终表示当前入口能用，可下一轮再看怎么规划，不要求立即调整。
- 关联：[已有历史习惯补记实现记录](../personal-dashboard-habit-history-timeline/map.md)。保留旧票状态，本次反馈作为交付后的使用体验记录。

## 3. 协作页：正常窗口下三栏太宽

- 当前左侧会话历史、中间开始／进行会话、右侧当前 context／工作内容同时展开，用户正常窗口大小下需要横向滚动，内容不能完整放下。
- 随着早间计划逐步从 Codex 移到 Dashboard，协作页的日常可用性更重要。
- 用户提出参考 Codex 的候选方向：可拖动的栏间分隔线、调整左右区域宽度、缩小辅助栏、暂时隐藏右侧内容；也可考虑更适合窄窗口的排列。
- 目标是在常用窗口尺寸下方便地完成会话并查看必要上下文。具体栏结构与交互尚未选定，不在本次重开整体视觉设计。

## 4. 语音识别：中文与中英混合输入

- 据用户当前体验，使用离线语言选择并选英语录音时，所说中文完全不能录入；用户经常中英混杂，单语言选择不能满足使用方式。
- 希望支持中文及中英混合；最好自动识别语言，减少手动选择。
- 下一轮再调查可行的语音输入方式，以及当前离线方案能否满足需求。自动识别是理想体验，尚未确认技术可行性；未选择模型、服务或新依赖，也未决定改用在线识别。

## 5. 语音入口与语言列表

- 当前“开始录音”在下方单独呈现。用户希望参考 Codex，在输入区域使用简单的麦克风按钮。
- 如果自动语言识别可行，希望日常无需选择语言；按钮状态及录音交互细节留待设计。
- 用户观察到语言选择中约有九个英语选项，认为没有必要：期望英语只保留美式英语，移除其他英语选项。
- 这里记录的是界面语言选项精简诉求，不授权删除系统语言包或其他系统资源。

## 6. Today 当日进展：聚焦活跃时段

- 当前从 00:00 到 24:00 展示完整时间轴，用户觉得跨度太长，日间安排不够集中。
- 希望参考 Outlook，默认更突出白天活跃时段，非活跃时段可以压缩，或通过上下滚动／展开查看完整范围。
- 用户举例的范围包括早上 6 点或 8 点到晚上 23 点或 24 点，也可能让晚间终点更早；这些只是例子，未确定默认起止时刻。
- 目标是更集中地看见当天重点安排，同时仍能查看其他时段。此显示需求与第 1 项的跨午夜归属分别讨论；已有时间轴方案不在本次改写。

## 2026-10-02 Grill 范围确认

- 用户确认六项全部保留，纳入本轮需求收敛。
- 本轮跳过 prototype；grill 只询问最重要的产品决定，普通交互细节由 agent 提出建议供整体核对。
- 收敛并确认共同理解后，整理 spec 到 GitHub issue；当前尚未开始产品实现。

### 已确认的关键决定

- **生活日边界：本地时间 04:00。** 用户确认该时刻适合睡眠作息。凌晨 00:00–03:59 默认继续前一个生活日的习惯、复盘和协作记录；允许手动选日期，真实事件时间与明确指定的日期保留原义。此为下一轮规则，尚未实现。
- **语音范围收窄。** 本轮采用手动选择中文或英文的单语言输入；中英混合与自动语言识别保留为下一轮研究项。用户希望先研究可行方式，再决定是否更换识别方案。本轮不以混输或自动识别作为验收条件。
- 麦克风入口调整与英语仅保留美式英语仍在本轮候选范围。中文可用性需在实际安装环境核查，不能仅凭已有选择框认定已支持或已验收。
- 已有 GitHub [语音票 #19](https://github.com/absurdwall/personal-dashboard/issues/19) 仍待真实识别质量验收；新 spec 需与其衔接。
- **Today 跨午夜时间轴。** 用户确认完整范围为当天 04:00 到次日 04:00，默认突出 06:00–24:00，两端可展开；凌晨片段标注次日日期／时间。凌晨打开页面或定位“现在”时，当前时间应可见。
- **相对日期按语境理解。** 当前生活日作为协作的默认参考，输入区明确显示目标日期；不能将“今天／明天”硬编码为固定偏移。用户明确指出：10 月 2 日凌晨 1 点，可能用“今天”或“明天”指代同一个 10 月 2 日。应结合句意、当前讨论及明确日期判断，避免过度追问。

### 2026-10-02 已确认的整体交互方案

- 历史习惯日期入口直接到达可操作的补记区，明确显示所选日期，沿用日常习惯完成／撤回的交互方式。
- 协作页保持现有三类内容；左右辅助栏可收起、栏间可拖动调宽并记住选择。窗口变窄时优先保留会话区域，辅助栏按需打开，常用窗口不依赖整页横向滚动。
- 输入框附近放麦克风按钮与紧凑的中文／美式英语选择，记住选择；转写进入可编辑草稿，由用户发送。
- 语义确实不清且会影响写入日期时，简短确认；可判断时直接采用对应日期，并让写入目标在现有确认流程中清楚可见。
- 历史已存记录保留原有归属；本轮不自动搬移或重写旧记录。明确指定的 Task 日期／时间仍表示实际日历日期／时间，在生活日时间轴中按其实际时刻展示。
- 用户确认整体交互方案；随后明确要求仅整理 spec，实施分组与 ticket 拆分留待后续讨论。混合识别留为后续研究。
