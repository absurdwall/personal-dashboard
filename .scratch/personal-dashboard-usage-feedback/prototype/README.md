# 当日连续时间轴 — throwaway prototype

问题：连续时间刻度是否能让用户清楚理解当前在一天中的位置？计划与事实如何并排阅读？

2026-09-23：用户明确选定 A（计划／实际双栏，共享连续时间刻度），并要求不再迭代原型。A 为后续实现的视觉与交互参考；本次确认未启动生产实现。

## 运行

在 personal-dashboard 项目目录执行：

```sh
node .scratch/personal-dashboard-usage-feedback/prototype/serve.mjs
```

打开终端打印的本地 URL。默认自动选择空闲端口；可用 DASHBOARD_TIMELINE_PROTOTYPE_PORT 指定端口。无需安装依赖。

- `?variant=A`：纵向计划／事实双栏，共享时间尺。
- `?variant=B`：单一事件时间流；重叠事项并排，单独事项占满。
- `?variant=C`：横向时间尺，计划／事实分行。
- 底部箭头或键盘左右键切换；滑块模拟当前时间，定位按钮滚动到现在；事项可点击查看详情。

沿用现有 .scratch/.../prototype 静态服务器惯例和 Today 页面导航／配色语境。这里是隔离的 Today 示意页面，未连接 Tauri，也未覆盖当前生产布局；不加载真实 Vault。独立静态文件不参与 frontend 生产构建。全部数据是合成示例，只存在内存。

06:00–23:00、每小时刻度和示例持续时间仅用于比较，不代表最终规格。未知发生时间单独展示；已确认事实与计划语义不因滑块变化而自动改变。原型不验证历史习惯补记。
