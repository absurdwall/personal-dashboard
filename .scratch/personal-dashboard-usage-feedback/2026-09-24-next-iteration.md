# 下一阶段需求记录 — 2026-09-24

状态：需求收集／待收敛，非已发布实现票。本次用户要求为下一步准备，明确后续 AI 功能不现在实施；本轮不修改产品代码、不安装依赖、不启动登录或运行真实规划。

## 近期：Tasks 与 Today 联动（3.0.2 候选）

### 用户反馈与目标

Tasks 和 Today 存在割裂：在 Tasks 新建今天 17:00 的任务，回到 Today 刷新后，日程时间轴上仍看不到。用户认为当天任务应在当天日程中出现，右侧的计划也应包含任务。

用户暂定属于 3.0.2、仍是 3.0 完善范围；版本尚未正式发布或排期。

### 应收敛的端到端行为

- 设置今天 17:00 的 Task，在 Today 刷新后能在 17:00 的时间轴位置直接看到任务名和时间，沿用目前已认可的单列可读卡片语境。
- 日期为今天但没有时刻的 Task，也应在当天界面清楚可见。建议放在“今日待安排／无具体时间”区，不虚构时刻或时长；具体呈现尚待确认。
- 用户提到的“右侧计划”也要包含当天 Task。后续在实际页面确认其所指区域：任务栏、当前安排或 AI 计划；不能把它擅自解释为改写 Daily Record 原文。
- 同一 Task 在 Tasks、Today、Calendar 中保持同一身份与状态；改名、改时刻、改日期、完成或撤回后展示一致，不生成第二份任务。
- 已有 Daily Record 计划与 Task 同时出现时，需要明确来源与去重规则；不能仅凭相同标题合并。完成 Task 与“已发生事实”的映射需明确，不把原定 17:00 当作实际完成时刻。

### 已有内容与下一步核查

现有领域约定：Task 是持久行动，带可选日期／时间；Task date 不是完成时间。既有 Tasks 正本应复用，不退回旧 Day task 文件，不另建 Today 专属任务存储。

[既有 4.0 票 04](../personal-dashboard-4/issues/04-today-shared-tasks.md) 已记录 Today 右侧任务栏与 Tasks 共享身份；[既有 4.0 规格](../personal-dashboard-4/spec.md) 已要求三入口一致。它们不能证明当前时间轴展示已完整，也不能代替用户路径复现。

下轮先核对“新建今天 17:00 → Today 刷新”的读取与展示链路；区分右侧列表可见而时间轴不可见、刷新未更新、日期／时区过滤等情况。本轮未复现或认定代码根因。

建议验收样例：今天有时刻、今天无时刻、改到明天后从今天移除、完成／撤回、Task 与文本计划同名、跨午夜、重启、切 Vault、窄窗口；实际 packaged 截图须能直接看到任务名。

## 后续：App 内 AI 规划入口（用户暂称 4.0／最终产品形态）

### 用户表达的方向

随着基础功能完善，将早间计划及更多 AI 相关流程挪到 App 内。右上角或设置中提供 Codex 登录入口，用户希望通过 OAuth authentication 登录，然后直接在 Dashboard 中运行早间计划，减少在多个工具之间切换。

本轮只记录产品方向，不设计完整交互、不创建可执行实施票。其他 AI 场景尚未定范围，不自动扩展成全部 Agent 工作流。

### 后续研究入口，不是已定架构

2026-09-24 查阅 [OpenAI 官方 Codex App Server 文档](https://learn.chatgpt.com/docs/app-server)：官方提供 account/login/start 的 ChatGPT 浏览器登录流程，返回授权 URL，由 app-server 处理本地回调，并提供登录完成／退出及账号状态接口。此能力可作为以后验证的集成候选；尚未在 Dashboard 中验证运行环境、分发方式和账号使用条件，不将其等同于已可直接嵌入的通用第三方 OAuth 登录服务。

后续验证应覆盖：支持的登录和本地运行方式；从 App 发起、查看进度／结果与处理失败；复用 canonical daily-loop 与 Tasks／Daily Record 正本；明确生成结果何时及如何写回。优先复用既有流程和边界，而不是另建第二套日记或任务数据。

### 版本命名注意

仓库已有 personal-dashboard-4 effort，主要是 Tasks、Calendar 及外部日常流程接线，且已有已实现部分。新的“AI 进入 App”作为独立后续方向记录；不重命名、不覆盖原有 4.0 规格与票。正式版本号在该阶段启动时再统一。
